OWNER-R1｜SEMANTIC_COMPOSITION_FIRST

Runtime Owner 只能读取已 admission 的组合语义结果。原始 Gate、Line、Driver、Layer、行星、Gene Keys 标签或关键词不能直接选择 owner。

OWNER-R2｜TAG_IS_ELIGIBILITY_NOT_DESTINATION

Eligible tag 只能缩小可能 owner 范围，不能独立决定 owner；还必须与组合意义所回答的架构问题和 scope 一致。

OWNER-R3｜DEEPEST_JUSTIFIED_OWNER

选择能够直接拥有该组合语义对象的最深既有 owner；如果已有充分证据支持下游 owner，不应停留在更宽泛的上游 owner。

OWNER-R4｜PRIMARY_AND_SECONDARY_ALLOWED

当组合意义跨越多个架构时，允许一个 primary owner 与零到多个 secondary owners；secondary owner 必须有明确跨 owner evidence。

OWNER-R5｜CARRIER_VS_C1_BOUNDARY

当意义关于载体容量、约束、完整性、承载或恢复基线时使用 K2A；当意义关于已配置的输入、感知、认知、调节、环境或连接方式时使用 C1。

OWNER-R6｜C2_VS_C4_SELECTION_BOUNDARY

当 Selection 描述体验中的注意／价值过滤时属于 C2；当它描述决策排除、承诺、资源配置或行动方向时属于 C4。

OWNER-R7｜C3_EXPRESSION_BOUNDARY

C3 必须存在明确的翻译、压缩、外化、媒介或表达阈值对象；只有 EXPRESSION tag 而无此类 context 不足以选择 C3。

OWNER-R8｜C5_IDENTITY_EVIDENCE_REQUIRED

只有组合明确涉及身份稳定、自我模型／角色连续、身份边界、身份漂移或身份重组时，才允许选择 C5。

OWNER-R9｜FEEDBACK_CONTINUITY_CYCLE_BOUNDARY

FEEDBACK／CONTINUITY 必须具有跨周期或反馈循环 context，例如适应、维护、恢复、重组、重复、重新进入或持续运行。

OWNER-R10｜CONFLICT_RETURNS_UNKNOWN

如果两个 primary owner 具有同等充分依据，而治理规则无法区分，则 primaryOwner 必须为 UNKNOWN；不得随机选择或使用模型偏好。

OWNER-R11｜CUSTOMER_STATE_REQUIRES_EVIDENCE

Owner assignment 只识别架构归属，不等于客户当前状态。任何声称客户目前过载、漂移、恢复、受阻或正在重组的结论，仍需要已 admission 的 current evidence。

OWNER-R12｜NO_OWNER_CREATION

只允许选择 K2A/CARRIER、C1、C2、C3、C4、C5 与 FEEDBACK/CONTINUITY；LLM 与 runtime composition 不得创造新 owner 或 alias。
