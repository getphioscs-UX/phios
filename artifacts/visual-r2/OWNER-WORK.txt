# 0. MASTER OBJECTIVE

The previous:

`PHI OS · PAGE CONSOLIDATION + PHI CONFIGURATION + PROFILE VISUAL MARKETING R1`

must **not be reverted at the information-architecture level**.

The reduced page architecture remains the preferred direction.

However, the current implementation has produced a visual regression:

- consolidated pages became excessively text-heavy;
    
- important visual assets disappeared from the visible reading flow;
    
- approved R2 assets exist but are not consumed meaningfully;
    
- several hero / feature positions resolve to empty or temporary-unavailable states;
    
- diagrams are frequently hidden behind generic “show related diagrams” interfaces;
    
- multiple sections use nearly identical card composition;
    
- PHI Configuration and Profile do not visually communicate that they are distinctive PHI OS products;
    
- flagship pages no longer have sufficient visual hierarchy to support marketing;
    
- pages often explain PHI OS rather than letting the visitor visually experience PHI OS;
    
- consolidation reduced duplication but also removed useful visual pacing.
    

This work must therefore perform:

> **PAGE CONSOLIDATION RETAINED
> 
> - GLOBAL VISUAL RECOMPOSITION
>     
> - APPROVED R2 ASSET CONSUMPTION
>     
> - FLAGSHIP PRODUCT VISUAL MARKETING
>     
> - RESPONSIVE / BILINGUAL / ACCESSIBLE PRESENTATION**
>     

Do **not** solve this by recreating dozens of explanatory routes.

Solve it by improving the composition of the routes that remain.

# 3. FIX THE GLOBAL ASSET RESOLUTION FAILURE FIRST

Current production must never expose:

`The visual is temporarily unavailable.`

when the approved R2 object exists.

Audit:

- R2 base path;
    
- case sensitivity;
    
- filename mismatch;
    
- extension mismatch;
    
- resolver mapping;
    
- URL escaping;
    
- CDN/public host;
    
- preload logic;
    
- lazy-load observer;
    
- CSP;
    
- fallback behavior.
    

Establish one canonical visual resolver.

Example conceptual API:

`resolveApprovedVisual(assetCode | canonicalFilename)`

It must return:

- canonical R2 URL;
    
- semantic role;
    
- width/height or aspect ratio;
    
- alt metadata;
    
- fallback policy.
    

Do not create page-specific ad-hoc R2 URLs once a shared resolver exists.

Add a zero-provider regression check that verifies every approved visual object required by public pages resolves successfully.

No screenshots are required for this object-existence check.

# 4. CREATE A GLOBAL VISUAL COMPOSITION SYSTEM

The problem must not be fixed page-by-page with unrelated CSS.

Create a shared composition grammar.

Required roles:

## A. HERO

Purpose:

- immediate identity;
    
- emotional entry;
    
- major product positioning.
    

Presentation:

- large;
    
- integrated with headline;
    
- meaningful crop;
    
- never tiny;
    
- never inside a generic card;
    
- no competing visual immediately beside it unless intentionally designed.
    

Suggested desktop:

`min(46–58vw, 920px)` visual field.

Suggested hero height:

approximately `560–760px`, responsive to viewport.

Mobile:

image first or carefully layered under headline.

Do not crop away the semantic center.

---

## B. PRIMARY FIGURE

Purpose:

- explain the core structure of the section.
    

Presentation:

- direct inline appearance;
    
- generous width;
    
- figure title supplied by HTML;
    
- readable at normal desktop width;
    
- tap/click for full resolution.
    

Suggested desktop:

`900–1280px` content width when diagram density requires it.

Never constrain a complex network figure to a 300px card.

---

## C. SUPPORTING FIGURE

Purpose:

- break long reading sections;
    
- clarify one bounded relationship.
    

Can use:

- 50/50 split;
    
- 40/60 split;
    
- alternating editorial layout.
    

---

## D. ILLUSTRATION

Purpose:

- experience;
    
- atmosphere;
    
- emotional rhythm;
    
- market communication.
    

It must not be treated as evidence or structural diagram.

---

## E. BRAND IDENTITY

Purpose:

- give each Book / flagship system its own visual identity.
    

Do not use branding assets as diagrams.

---

## F. STATE ILLUSTRATION

Use only for actual states:

- no saved content;
    
- no matching result;
    
- permission required;
    
- temporary loading failure.
    

Do not show scary warning UI for an ordinary empty state.

# 5. GLOBAL PAGE RHYTHM RULE

No major marketing/public page should contain more than:

> **two substantial text-only sections consecutively**

without one of:

- meaningful figure;
    
- illustration;
    
- interactive product surface;
    
- preview;
    
- data/result object;
    
- contextual CTA composition.
    

Exception:

long-form editorial content such as Founder essays or books may deliberately use longer reading sections, but still require editorial visual pacing.

`heading → paragraph → cards → heading → paragraph → cards → heading → paragraph`

throughout an entire page.

`Hero`  
→ `clear value`  
→ `visual proof`  
→ `interactive/product experience`  
→ `deeper explanation`  
→ `figure`  
→ `decision/CTA`  
→ `continuity`
