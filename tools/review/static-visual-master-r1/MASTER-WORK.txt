# PHIOS 全站静态视觉资产接线与页面美化 Master Work R1

## 一、执行目标

在当前 PHIOS 仓库中完成全站公开页面的视觉改进，优先利用已经上传到 `phios-public-assets` 的资产，尤其是本次提供的 19 张商业 WebP。

工作必须落到实际页面、实际组件和实际资产解析路径，不能只更新登记、生成报告或新增没有消费者的配置。

最终需要做到：

1. 现有商业图片出现在正确的商品说明、付费解锁、服务、会员和账户位置。
2. 主要页面减少超大标题、无内容占位、重复横幅和过大段间距。
3. 免费确定性命盘、付费商品海报、已接受报告视觉、知识图表各自保持正确用途。
4. 中英文界面保持完整，手机和桌面均可读。
5. 图片显示、免费路径、分页和保存后重开不产生 provider 调用。
6. 保留已接受正文、diagram、视觉资产、历史订单、价格与客户权益。
7. 提交可审阅的代码差异及真实零成本验证结果。

请持续执行，不要只返回计划，不要将修复工作交回让我重复运行相同失败命令。

## 三、授权范围与禁止事项

本轮允许：

- 读取当前仓库、Git 状态、相关登记、配置和检查。
- 修改页面、样式、组件、资产映射和必要检查。
- 使用已有公开资产进行只读验证。
- 运行本地构建、零 provider 测试和浏览器预览。
- 从已有接受的原图导出必要的响应式副本。
- 保留并合并当前未提交工作。

本轮禁止：

- 自动 commit、push、部署或生产迁移。
- 删除 R2 对象、历史资产或源码。
- 新增付费模型测试或实际付款。
- 启用全局 LIVE checkout。
- 新建或重复修改已核验的 Stripe 商品。
- 因美化工作改变商品价格、权益或 provider 成本池。
- 用商品海报替代客户真实命盘。
- 覆盖另一窗口正在修改的内容。
- 修改冻结哈希以绕过检查。
- 削弱 schema、断言、安全边界或权限检查。
- 生成 delta zip 代替实际集成。

遇到不涉及上述禁止事项的常规实现选择，直接按现有架构完成，不反复请求确认。

## W01｜建立当前页面与消费者清单

从当前仓库 sitemap、导航、路由、重定向及实际页面建立清单。

至少覆盖：

- 首页。
- World 及其公开视图。
- Explore 及子页面。
- Reality。
- Perspectives。
- Personal、Relationship、Profile、Tarot、I Ching。
- Knowledge、Concepts、Search、Ask。
- Articles 目录及文章模板。
- Figures。
- Books 目录与八册详情。
- Academy、学习路径与课程消费者。
- Professional、Financial、Services、Appointments、Authority、Reports。
- Membership。
- Account。
- About、Founder、Thesis、Research。
- Terms、Privacy、AI Disclosure。
- 共用 header、footer、空状态和图片查看器。

区分：

- 规范页面。
- 历史别名或重定向。
- 公共初始状态。
- 延迟加载状态。
- 折叠内容。
- 登录或付费状态。
- 下载与打印消费者。

不能只统计 `<img>`。同时检查：

- CSS 背景。
- `<picture>`、`srcset`。
- SVG 与 canvas。
- 动态 resolver。
- 页面注入的资产。
- 隐藏查看器与占位图。

将每个位置标为：

- 已正确显示，保留。
- 已接线但显示异常。
- 存在资产但缺消费者。
- 当前证据不足。
- 此位置不需要图片。

**完成条件：** 有实际页面与插槽清单，不把瞬时空 `src`、折叠内容或隐藏查看器认定为缺图。

## W02｜核对资产登记与精确对象身份

读取现有商品视觉登记、公共资产登记、页面 presentation 配置及实际 resolver。

至少检查：

`content/web-production/registries/commerce-product-visuals-v1.json`

以及当前实际使用的公共视觉登记与消费者。

不要因为参考材料出现某个版本号，就把历史登记设为当前权威。

逐项核对：

- product ID。
- asset code。
- R2 object key。
- 页面与组件。
- 使用角色。
- 方法。
- locale。
- active 状态。
- 接受记录。
- 实际销售或交付范围。

若塔罗和易经仍缺少登记，将它们补入现有合理入口，并接到真实消费者。

不得新建平行 resolver 或另一套没有消费者的登记体系。

附件中的 `(1)`、`(2)` 等本地重复下载后缀不能写进 R2 key。

对象 key 中已有特殊字符，必须按照实际对象身份解析。不得先“修正”文件名再假设远端存在。

**完成条件：** 登记和消费者对应；不存在只登记不显示的虚假完成。
