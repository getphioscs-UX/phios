# Product architecture / evidence model / cross-system contract

## Reuse and compatible versioning

Canonical page: /perspectives/profile/. Existing seven modes, item banks, PFIGs and bilingual assessment reports remain intact. The same profile account owner writes new typed artifacts in runtime_artifacts/runtimes, with existing encryption and verified server identity. No parallel store, identity, scoring, consent token, model, market API or report lifecycle. Existing assessment schema/type is unchanged. New pure normalization/comparison is functions/profile/personal-evidence-records.js; RR assembly remains personal-evidence-report-adapter.js. Local contract: content/profile/successors/personal-evidence-r1/contracts/personal-reality-evidence-local-r1.json.

## Evidence and claims

Typed customer accounts keep observation period separate from recording time, source reference/provenance, language, owner, version, correction relation, privacy, sharing and verification limits. Self-report, feedback and document references stay RECORDED / NOT_INDEPENDENTLY_VERIFIED. File bytes are not admitted or inspected; no independent-verifier endpoint exists. Existing assessment/task classes remain native. Explicit activity classification can yield a traceable SYSTEM_DERIVED candidate; free text ERP alone cannot yield a qualification. User-selected capability areas are separately labelled. A claim is linked to its record/version and customer-supplied support/counter-evidence. Comparing requires the same claim; context changes, missing outcomes and contradictory accounts remain distinct. No master score or false percentage.

## History and report

Immutable encrypted revisions; stale edit/selection rejected. The pure comparison helper accepts the same scale/version/context without claiming growth; different versions are NOT_COMPARABLE. A historical assessment comparison UI is not yet connected; the visible new timeline is experience revision history only. Corrections never overwrite issued content. RR evidence/unknown/boundary sections are reused for a bilingual experience-only consumer. No fabricated assessment and no forced 16-page engine. HTML snapshots persist encrypted and reopen with owner checks. Source changes label old reports historical; revocation/expiry of any source denies new reads. Browser print-to-PDF tested locally; no production PDF service/storage claim. Previous assessment/PFIG dossier is still a separate preserved deliverable.

## Cross-system contract

Selected exact record versions + explicit purpose + per-request consent + at most ten minutes. RDG visibility/permission evaluation is reused; not a newly issued access token. Re-read every source on projection; no automatic target save.

| Target | Actual local result | Remaining connection |
|---|---|---|
| Ask | Minimal source-preserving reference package; Provider 0 | Existing contextual Ask consumer has not consumed these experience packages; no new Ask engine |
| Financial | Context-only package; no balances, account numbers, cash-flow or advice authority | Existing Financial intake must accept the scoped package separately |
| World | Personal references retained; WORLD_DATA_UNAVAILABLE | No current jobs/qualification dataset queried; use existing World source owner when qualified |
| Configuration | Interpretation remains null with separate observed-evidence references | No authorized existing Configuration report supplied; no symbolic interpretation promoted to fact |
| Navigation | Existing createNavigationContract called with constraints and unknowns | Receiver execution/history not closed; no resignation command or invented action |

The old assessment-to-My-Reality selected handoff and old Financial/career/relationship contracts remain unchanged. A reference package is not an integrated receiver or saved target record. These product connections remain PARTIAL, not blocked by a claimed need for provider spending. No target owner or concurrent Configuration files were overwritten.

## Privacy and security

Server-held verified identity only; body owner fields forbidden; same-origin JSON posts; strict field allowlists and byte limit; encryption at rest; no-store responses; escaped report text and restrictive report CSP. No upload endpoint, public index, paid generation or sensitive logs. Revocation is logical access denial, not physical deletion; downloaded copies cannot be recalled. Retention is explicit (UI 30 days, API maximum 366), checked on reads, but physical purge of expired encrypted revisions remains unimplemented. Production retention/backup policy and Malaysian privacy review remain release gates; no PDPA compliance claim.

## Product scope

Six areas mount only on loopback with evidence=1; writes also require server flag PHIOS_PERSONAL_EVIDENCE_LOCAL=true. Production hostname fails closed even if the flag is supplied. Existing page remains the public route. Language switching retains unsaved form entries and original source-language choice. No production activation or entitlement change. Existing subscription registry retains RM19/month. The owner brief specifies a future maximum USD3/month/user; actual reservation/settlement enforcement for a new Personal Evidence model action is not admitted or tested. Paid narrative remains disabled, including when an account is subscribed.
