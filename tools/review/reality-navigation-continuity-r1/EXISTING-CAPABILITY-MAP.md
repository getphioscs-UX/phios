## Context and change policy

Only explicitly selected, confirmed, active, case-scoped records enter the pack. Confirmation is never external verification. Branch records stay out of main context unless explicitly selected for main. Corrections invalidate current understanding, decisions, next actions and checkpoints conservatively; they do not generate a replacement answer. Reconfirmation and a new user-reviewed understanding are required. Withdrawn/deleted/expired items never return via an old checkpoint. Deletion erases the selected content from the owner record and its audit snapshot copies; event IDs/reasons remain.

Context is bounded in complete units, including metadata: at most 32 selected records and 12,000 serialized characters by default. Exclusion samples are bounded; counts by reason remain visible. No chat transcript is retained. External source text is data, not executable instructions. Zero-provider tests do not prove future LLM prompt-injection resistance.
