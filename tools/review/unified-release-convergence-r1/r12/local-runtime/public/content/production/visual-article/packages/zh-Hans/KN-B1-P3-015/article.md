# 运行网络如何形成状态、反馈、重组与连续性

一个运行中的系统，很少由单一节点独立决定当前状态。更常见的情况是：多个节点、关系、权重、约束与时间条件同时参与，形成一个暂时稳定却持续变化的网络状态。要理解 Runtime 如何延续，就必须同时理解状态、反馈、重组与连续性。

## 状态来自网络，而不是单一原因

所谓“当前状态”，并不是把所有节点简单相加。不同节点在同一时间窗口中具有不同的激活程度，不同关系承担不同的连接作用，不同约束又限制哪些变化可以发生。

因此，一个网络状态是分布式形成的。某些部分可能非常活跃，某些部分暂时沉默；某些连接具有较高权重，另一些连接只在特定条件下参与。当前现实由这些关系共同组织，而不是由一个隐藏的中央控制器单独决定。

## 输出会重新成为输入

网络一旦运行，就会产生结果。这些结果不会永远停留在系统之外，它们常常改变下一轮运行条件。当输出再次进入网络，反馈便形成。

反馈并不只是一个简单的圆圈。一次结果可能改变某个节点的权重，可能加强或削弱某条连接，也可能改变系统对后续信号的处理方式。于是，同样的输入在不同历史状态中，可能产生不同结果。

反馈让 Runtime 不只是重复执行，而能够带着前一次运行留下的状态继续变化。

## 重组让网络在条件变化后继续运行

当原有连接无法再适应新的条件，网络需要的不一定是彻底重置。它可以改变局部权重、建立新的连接、弱化旧关系，或者重新划定边界。这就是重组。

重组意味着系统的组织方式发生变化，但并不要求所有结构同时消失。某些关系被保留，某些关系被替换，新的运行路径由此出现。网络因此能够在不回到零状态的情况下回应新的现实。

## 连续性不等于保持不变

我们容易把连续性理解成“原来的结构一直存在”。但真正能够持续的系统，往往恰恰需要变化。连续性更重要的条件，是在变化之后仍然保留足够的关系，使前后状态可以连接起来。

只要关键状态能够传递，必要约束仍然存在，网络就可以在结构调整后继续运行。于是，连续性与变化并不矛盾。没有变化，系统可能失去适应能力；没有连续性，变化又会变成彼此断裂的瞬间。

## 反馈不保证自动稳定

反馈能够带来调整，却不会自动产生稳定。某些反馈可能放大变化，某些重组可能形成新的失配，某些网络也可能在约束改变之后失去原有连续性。

因此，不能把“有反馈”直接理解为“会自我修复”，也不能把网络存在本身理解为系统必然能够恢复原状。Runtime 的持续取决于关系、权重、约束与反馈在具体条件中的共同运行。

## 从网络运行进入生命载体

状态、反馈、重组与连续性把前面的激活、权重、场与时间连接成了一个完整的网络级 Runtime。到这里，问题也开始改变：如果一个 Runtime 要长期存在，它必须由什么承载？

下一步将进入生命载体。持续运行不只需要抽象关系，还需要一个有限结构去承受成本、保存状态、接收输入并维持内部连接。网络如何继续，最终会落到载体如何继续运行。
