# 5. `definition`

**Decision Object** 是 Navigation 在进入任何选项比较、风险判断、行动建议或现实路径之前，必须先明确的“真正正在被决定的事项”。

它不是客户最先说出口的动作，也不是一句宽泛愿望，更不是系统根据某种方法自动补出的隐藏问题。

例如：

```
“我要不要辞职？”
```

可能仍然不是最终 Decision Object。

真正需要决定的可能是：

```
是否继续以当前工作结构交换收入与稳定
```

也可能是：

```
是否在未来六个月内建立一条能够降低对现有工作的依赖路径
```

或者：

```
是否需要改变当前工作方式，而不是离开职业本身
```

因此：

> **Decision Object 不是动作名称，而是一个需要在现实条件下作出取舍、承担后果并能够被后续结果检验的问题。**

---

# 6. `navigationMeaning`

Navigation 不能在问题尚未被清楚定义时直接比较方案。

如果 Decision Object 错误，后续即使拥有：

- 更多资料；
- 更好的模型；
- 更准确的 Profile；
- 更完整的 Financial Reality；
- 更多 Method Readings；
- 更复杂的 AI；

最终也只是在更高效率地回答错误问题。

因此 NAV-01 是所有后续 Navigation modules 的入口门。

其顺序必须是：

```
User Concern
↓
Clarify Decision Object
↓
Confirm What Is Actually Being Decided
↓
NAV-02 Current Position
↓
后续 Navigation
```

而不是：

```
User Concern
↓
Method / AI
↓
Recommendation
```


这些可以帮助识别：

- 用户是否把症状误当成问题；
- 一个动作背后是否存在更核心的取舍；
- 当前问题是否实际上包含多个独立决定。

# 9. `inputAuthorityClasses`

NAV-01 接受以下来源类别：

```
USER_REPORTED
DIRECTLY_OBSERVED
CURRENT_EXTERNAL_EVIDENCE
REPORT_INTERPRETATION
SYMBOLIC_READING
PROFESSIONAL_INPUT
PRIOR_NAVIGATION_STATE
```

但它们的权重不同。

优先顺序不是“哪个系统最完整”，而是：

```
用户明确表达的决定意图
+
现实中可验证的条件
+
与该问题直接相关的既有证据
```

Symbolic / Method interpretation 只能作为：

```
QUESTION_REFINEMENT_CONTEXT
```

不得取得：

```
DECISION_OBJECT_OWNERSHIP
```

# 10. `allowedInference`

NAV-01 可以推断：

### A. 表面动作可能不是最终问题

例如：

```
“我要不要搬家？”
```

可以提示进一步区分：

```
居住成本
通勤
照护
工作地点
生活质量
家庭支持
```

但不能替客户认定其中哪一个才是“真正原因”。

### B. 一个问题可能包含多个 Decision Objects

例如：

```
“我要不要离婚？”
```

可能同时包含：

```
关系是否继续
共同居住是否继续
共同财务怎样处理
孩子照护怎样安排
什么时候行动
```

系统可以识别问题需要拆分。

### C. 用户当前表述可能过宽

例如：

```
“我人生下一步怎么办？”
```

系统可以要求收窄到当前真正需要承担的决定。

### D. 当前语言可能混合目标与动作

例如：

```
“我要创业，因为我想自由。”
```

系统可以区分：

```
动作 = 创业
价值/目标 = 自主
```

但不能在 NAV-01 阶段判定创业是否适合。

---

# 11. `forbiddenInference`

NAV-01 严禁：

### A. 从 Profile 直接推定客户真正想决定什么

禁止：

```
你的 Profile 显示你重视自主，所以你真正想辞职。
```

### B. 从 Method Reading 推定隐藏问题

禁止：

```
八字显示当前压力增加，所以你真正的问题是职业。
```

### C. 从 Tarot / I Ching 推定真实动机

禁止：

```
牌显示你其实想离开。
```

### D. 从历史行为自动定义当前 Decision Object

过去做过什么不能自动决定当前问题。

### E. 把系统自己的产品分类当成客户问题

禁止：

```
这是 Career Navigation。
```

除非客户问题确实已被确认属于该范围。

### F. 偷偷把“想了解”升级成“必须决定”

例如：

```
我只是想知道为什么最近很累
```

不能自动升级成：

```
是否需要辞职
```

# 12. `decisionEffect`

NAV-01 的直接作用是：

```
DECISION_SCOPE_FORMATION
```

以及：

```
OPTION_SPACE_BOUNDARY
```

它不直接决定：

```
OPTION_ELIGIBILITY
OPTION_WEIGHT
DECISION_THRESHOLD
FINAL_ACTION
```

NAV-01 只决定：

> **后续 Navigation 究竟在回答哪一个问题。**

---

# 13. `decisionThresholdEffect`

```
NO_DIRECT_THRESHOLD_CHANGE
```

但如果 Decision Object 被重新定义，后续所有 threshold 必须重新计算。

例如：

```
“我要不要辞职？”
```

与：

```
“我要不要先建立6个月可验证的职业替代路径？”
```

虽然来自同一个原始担忧，但：

- 可逆性；
- 时间；
- financial threshold；
- action scale；

都会完全不同。

因此：

> **Decision Object 一旦改变，后续 Navigation 不得沿用旧 threshold。**

---

# 14. `authorityBoundary`

NAV-01 可以：

- 帮用户澄清问题；
- 拆分复合问题；
- 暴露模糊表述；
- 区分动作、目标与待解决问题；
- 提出需要进一步确认的问题。

NAV-01 不可以：

- 替用户选定人生目标；
- 把系统解释当成用户意图；
- 自动产生最终问题；
- 以专业身份覆盖客户本人的问题定义权。

---

# 15. `humanDecisionBoundary`

最终 Decision Object 必须保持：

```
HUMAN_CONFIRMABLE
```

即使系统提出：

> “听起来你真正需要比较的可能不是‘辞不辞职’，而是‘当前工作结构是否仍值得继续，以及是否应先建立替代路径’。”

客户仍必须能够：

```
CONFIRM
REVISE
REJECT
SPLIT
```

系统不得因为客户没有主动纠正，就自动把候选问题提升成事实。

# 24. `revisionTriggers`

Decision Object 必须在以下情况重新检查：

```
userGoalChanged
newConstraintAppeared
newResponsibilityAppeared
newEvidenceChangesProblemScope
currentSituationMateriallyChanged
professionalInputReframesIssue
userRejectsPriorDecisionObject
multipleDecisionObjectsDetected
timeWindowChanged
```

一旦触发：

```
Decision Object → REOPEN
```

后续 Navigation 必须重新建立。

# 25. Canonical Runtime Rule

冻结为：

> **Navigation must not compare options until the object of decision is sufficiently clear to be stated, challenged, and confirmed.**

中文：

> **在决策对象尚不足以被清楚表达、质疑与确认以前，Navigation 不得开始比较选项。**

---

# 26. Canonical Boundary Rule

> **A system may help clarify what is being decided; it may not silently decide what the user’s real problem is.**

中文：

> **系统可以帮助澄清“正在决定什么”，但不能悄悄替用户定义“你真正的问题是什么”。**

---

# 27. Customer Projection Example

客户不应该看到：

```
NAV-01 PASS
Decision Object normalized
```

应该看到：

> **你现在真正需要决定的，可能还不是“辞不辞职”。从你已经提供的情况看，目前至少有三个不同问题混在一起：工作负荷是否还能继续、现在的职位是否仍值得保留，以及是否需要先建立另一条可行路径。先把这三件事分开，后面的比较才不会把不同问题当成一个答案。**

然后提供：

```
这就是我要决定的
需要调整
拆成几个问题
```

# 28. Internal State Model

建议状态：

```
UNFORMED
CANDIDATE
USER_CONFIRMED
SPLIT_REQUIRED
REOPENED
```

其中只有：

```
USER_CONFIRMED
```

才能正式进入 NAV-02。

特殊情况：

如果是极简单、低风险、明显目标的问题，可以允许：

```
SYSTEM_CANDIDATE + USER_CONTINUES
```

作为弱确认，但高风险决定不得这样处理。

# 5. `definition`

**Current Position** 是 Navigation 在已经确认“正在决定什么”以后，对用户此刻所处现实位置的受限重构。

它回答的不是：

> “你是什么样的人？”

也不是：

> “你理想上想去哪里？”

而是：

> **“在这个具体决定发生的此刻，你实际上站在哪里？”**

Current Position 必须由与当前 Decision Object 直接相关的现实条件组成，而不是把客户所有已知资料全部堆在一起。

例如客户已经确认：

```
Decision Object:
未来六个月内，是否应该离开当前工作，
还是先建立替代收入与新的工作路径？
```

那么 Current Position 可能包括：

```
当前收入结构
现金缓冲
债务与固定责任
家庭依赖者
工作负荷
身体可承受程度
已有技能与替代机会
当前合约 / notice period
地域限制
时间窗口
```

却不应该因为系统拥有客户全部资料，就自动加入：

```
所有历史报告
全部 Personality 内容
所有 Tarot readings
全部 Book 阅读记录
所有过去关系问题
```

因此：

> **Current Position 不是客户资料总和，而是与当前决定有因果或约束相关性的现实位置。**

---

# 6. `navigationMeaning`

Navigation 从来不是在真空中比较选项。

同一个选择，在不同当前位置上可能代表完全不同的风险、成本与可行性。

例如：

```
“离职”
```

对于：

```
12个月现金缓冲
无债务
没有依赖者
已有下一份工作候选
```

与：

```
1个月现金缓冲
房贷
两个依赖者
医疗责任
没有替代收入
```

虽然动作名称完全相同，但它们并不是同一个现实决定。

因此 NAV-02 的核心作用是：

> **把 Decision Object 放回真实资源、责任、约束与时间里。**

只有这样，后续的：

- Closed vs Open Conditions；
- Reversibility；
- Capacity；
- Scenario Space；
- Decision Sufficiency；

才有现实意义。

```

```

如果：


则：


共同决定。

## 已关闭与仍开放的条件｜先分清什么已经不能改，什么仍然可以选择

> **为什么决定以前必须先区分既定条件与仍可选择的空间？**

## 3. `canonicalTitleEn`

## 4. `canonicalQuestion`

```
为什么决定以前必须先区分既定条件与仍可选择的空间？
```

# 5. `definition`

**Closed vs Open Conditions** 是 Navigation 在已经建立 Current Position 以后，对当前决策空间进行第二次分层：把已经发生、已经锁定、无法由当前决定直接撤销的条件，与仍然能够通过选择、行动、等待、谈判、准备或重新配置而改变的条件分开。

它回答的不是：

> “什么是好，什么是坏？”

也不是：

> “什么值得坚持，什么应该放弃？”

而是：

> **“在当前这个决定里，哪些条件现在只能被承认并带着走，哪些条件仍然拥有真实的改变空间？”**

例如：

```
事实：
过去三年已经投入某职业路径
```

这部分属于：

```
CLOSED / INHERITED CONDITION
```

因为过去时间不能被撤回。

但：

```
未来是否继续投入三年
```

仍然属于：

```
OPEN CONDITION
```

同样：

```
已经发生的关系事件
```

不可撤销；

但：

```
如何回应
是否继续共同生活
未来怎样设置边界
```

仍然可能开放。

因此：

> **NAV-03 不判断过去应不应该发生，而是确认从当前时点开始，真正还剩下哪些决策自由度。**

---

# 6. `navigationMeaning`

如果 Navigation 不区分 Closed 与 Open，系统很容易犯两类相反错误。

第一类：

> 把已经无法改变的条件继续当作候选选项。

例如：

```
“如果当时没有买这套房就好了。”
```

这可以进入复盘，却不能作为现在的实际选项。

第二类：

> 把仍然开放的条件误认为已经固定。

例如：

```
“我已经在这个行业十年，所以以后只能继续。”
```

过去十年已经发生，但未来十年并没有因此自动关闭。

因此 NAV-03 的作用是：

```
Current Position
↓
Separate Inherited Reality
from
Remaining Choice Space
↓
Define Real Option Space
```

只有这样，后续 Navigation 才不会：

- 浪费资源处理不存在的选项；
- 把历史惯性误当成现实必然；
- 把理论可能误当成当前可行；
- 把暂时不能做误写成永远不能做。

# 10. Core Condition Classes

建议 runtime 至少区分五类，而不是只有二元 Closed / Open：

```
CLOSED
OPEN
CONDITIONALLY_OPEN
NOT_YET_OPEN
OPENNESS_UNKNOWN
```

---

## A. `CLOSED`

当前决策无法直接改变。

例如：

```
past event
already elapsed time
already incurred historical loss
already disclosed information
completed transaction
confirmed irreversible biological/legal event
```

---

## B. `OPEN`

当前仍存在真实选择空间。

例如：

```
whether to continue
whether to pause
whether to negotiate
whether to apply
whether to allocate new resources
```

---

## C. `CONDITIONALLY_OPEN`

理论上能改变，但必须满足前置条件。

例如：

```
move country
```

可能需要：

```
visa
income
school
housing
consent
```

因此不是当前完全开放，也不是关闭。

---

## D. `NOT_YET_OPEN`

方向可能存在，但当前尚未取得现实资格。

例如：

```
创业
```

客户目前没有：

```
minimum capital
time
legal permission
required skill
```

不应写成：

```
IMPOSSIBLE
```

而是：

```
NOT_YET_OPEN
```

---

## E. `OPENNESS_UNKNOWN`

系统不知道能不能改变。

例如：

```
是否可以提前终止合同
是否能调换岗位
是否有资格申请某项安排
```

需要进一步确认。

---

# 14. `decisionThresholdEffect`

Closed / Open 分类本身不直接决定最终 threshold，但会改变：

```
how many real options remain
how reversible the situation is
how urgent information gathering becomes
whether preparation should precede action
```

例如：

如果：

```
only one condition remains open
```

后续 decision space 会显著收窄。

如果：

```
multiple conditions remain open
```

则可以允许：

```
staged experiment
comparison
delay for information
```

因此：

# 32. Customer Projection Example


客户可以看到：

> **现在已经不能改变的是：**现有租约已经生效，过去支付的费用也无法收回；这些不再是接下来需要重新选择的部分。
> 
> **仍然开放的是：**你可以开始寻找新住所、调整预算，并决定是否继续住到租约结束。
> 
> **目前有条件开放的是：**提前搬走并非一定做不到，但需要先确认转租或提前终止条款，以及新住所是否真正可行。
> 
> **仍然未知的是：**目前没有足够资料确认提前退出的实际费用，因此这部分不应该被当成已经关闭，也不能被假设为免费可行。

# 5. `definition`

**Time** 是 Navigation 对“何时进入现实”这一条件的正式处理。

它不是简单记录日期，也不是预测未来，更不是寻找某个神秘的“最佳时机”。

它回答的是：

> **当一个选择仍然存在时，时间的推进会怎样改变它的成本、可行性、风险、可逆性、信息质量与未来空间？**

例如：

```
离开当前工作
```

如果发生在：

```
12个月现金缓冲
下一份工作已明确
家庭责任较低
```

与发生在：

```
1个月现金缓冲
医疗支出刚增加
家庭责任上升
```

虽然动作名称相同，现实意义已经不同。

同样：

```
等待三个月
```

可能：

- 增加资料；
- 增加储蓄；
- 让条件成熟；

也可能：

- 失去机会；
- 增加成本；
- 让可逆选项关闭。

因此：

> **NAV-04 不寻找“完美时间”，而是判断时间正在增加什么、减少什么，以及它怎样改变当前选择空间。**

---

# 6. `navigationMeaning`

Navigation 不能把时间当作背景。

时间本身会改变：

```
option availability
option cost
option reversibility
evidence quality
resource position
responsibility load
exit difficulty
opportunity window
```

因此 NAV-04 必须在后续所有重大判断之前明确：

```
Now
vs
Later
```

究竟是不是同一个选择。

如果 Navigation 忽略时间，就容易犯两种错误：

### A. 把“以后可以”误当成“以后仍然一样”

例如：

```
以后再转行
```

不一定等于：

```
同样成本
同样机会
同样恢复空间
```

### B. 把“现在还不确定”误当成“应该继续等”

未知存在，并不自动说明等待有价值。

# 10. Core Time Classes

建议 runtime 至少区分：

```
FIXED_DEADLINE
OPEN_WINDOW
CLOSING_WINDOW
PREPARATION_PERIOD
WAITING_PERIOD
RECOVERY_PERIOD
TIME_SENSITIVE_UNKNOWN
NO_MATERIAL_TIME_EFFECT
```

---

## A. `FIXED_DEADLINE`

例如：

```
contract expiry
application deadline
legal filing date
school enrollment deadline
```

这种时间条件可以直接改变 option availability。

---

## B. `OPEN_WINDOW`

当前仍然拥有进入某项行动的现实时间空间。

例如：

```
仍有4个月可以准备搬迁
```

---

## C. `CLOSING_WINDOW`

继续等待会实质减少选项。

例如：

```
offer expires in 7 days
visa window closing
medical timing boundary
```

这里不代表必须行动，但 waiting cost 上升。

---

## D. `PREPARATION_PERIOD`

等待能够增加：

```
resources
evidence
capability
coordination
```

因此等待本身具有积极作用。

---

## E. `WAITING_PERIOD`

当前等待并没有明确增加现实条件，只是：

```
decision deferred
```

这类状态必须继续观察。

---

## F. `RECOVERY_PERIOD`

系统需要时间恢复到能承担决定的状态。

例如：

```
身体恢复
家庭稳定
团队重新配置
```

但 NAV-04 不重新定义 Recovery 机制；它只消费已经建立的恢复需求。

---

## G. `TIME_SENSITIVE_UNKNOWN`

系统知道时间可能重要，但不知道具体边界。

---

NAV-04 可以：

## A. 判断等待是否正在增加信息价值

## 不行动｜什么都不做，也正在让现实继续发生

> **为什么“什么都不做”并不是没有选择？**

# 5. `definition`

**Inaction** 是 Navigation 对“暂不采取新动作”这一状态的正式处理。

它不是：

```
NO DECISION
```

也不是：

```
NO CONSEQUENCE
```

而是：

> **在当前结构继续运行的情况下，选择不介入、不改变、不终止、不重新分配资源时，现实会沿着什么方向继续。**

因此，Inaction 必须被当成一种真实路径进入候选空间。

例如：

```
不辞职
```

不是空白。

它意味着：

```
current job continues
current income continues
current workload continues
existing constraints continue
future options continue to change
```

同样：

```
不处理债务
```

也不是：

```
nothing happened
```

而可能意味着：

```
interest continues
liquidity changes
future borrowing capacity changes
```

因此：

> **NAV-05 的核心不是鼓励行动，而是防止“不行动”被错误地当成没有成本、没有方向、没有责任的中立状态。**

---

# 6. `navigationMeaning`

Navigation 如果不把 Inaction 放进候选空间，就会形成一个系统性偏差：

```
Action = choice
Inaction = default
```

这会导致现状自动获得不需要解释的特权。

真正合理的结构应该是：

```
ACT
WAIT
MAINTAIN
PAUSE
MONITOR
EXIT
```

都属于可能的导航响应。

其中：

```
MAINTAIN
```

也必须重新取得资格。

因此 NAV-05 的作用是：

```
Time-Bounded Decision Space
↓
Model Inaction as a Path
↓
Project Continuation Consequences
↓
Compare Action and Non-Action
```

它并不自动提升“行动”权重。

它只是让：

> **继续原样**

也必须接受和其他路径一样的现实检验。

---

# 10. Core Inaction Classes

建议 runtime 至少区分：

```
STABLE_MAINTENANCE
PASSIVE_CONTINUATION
ACTIVE_MONITORING
DEFERRED_DECISION
ACCUMULATING_COST
OPTION_DECAY
INACTION_CONSEQUENCE_UNKNOWN
```

---

## A. `STABLE_MAINTENANCE`

不行动本身仍然合理，而且当前系统：

```
remains functional
cost acceptable
future options preserved
```

例如：

```
暂不换工作
```

同时：

```
现金流稳定
负荷可承受
未来选择未明显减少
```

这种 Inaction 可以继续保留资格。

---

## B. `PASSIVE_CONTINUATION`

没有新动作，但现有结构继续。

例如：

```
继续现有岗位
继续当前家庭安排
继续原投资配置
```

尚未证明好或坏，只是：

```
current trajectory continues
```

---

## C. `ACTIVE_MONITORING`

暂不改变，但设置：

```
observable indicators
review date
trigger conditions
```

这不是 passive inaction。

例如：

```
三个月内继续当前工作，
每月检查睡眠、工时、储蓄和招聘机会
```

---

## D. `DEFERRED_DECISION`

决定被推迟，但没有清楚的：

```
review point
information target
preparation goal
```

这类状态必须被明确标示。

---

## E. `ACCUMULATING_COST`

继续不行动会增加：

```
financial cost
health burden
relationship burden
maintenance burden
opportunity cost
```

但必须有现实依据。

---

## F. `OPTION_DECAY`

继续不行动会使：

```
some options become harder
more expensive
less reversible
or unavailable
```

它与 NAV-04 的 Closing Window 相连。

---

# 11. `allowedInference`

NAV-05 可以：

## A. 识别现状继续本身会产生后果

例如：

```
每月持续赤字 RM2,000
```

则：

```
no action
→ liquidity declines over time
```

这是合法 consequence projection。

---

## B. 识别维持现状需要持续支付成本

例如：

```
current workload = 60h/week
```

如果用户明确报告：

```
recovery remains insufficient
```

可以标记：

```
continuation carries ongoing capacity cost
```

但不能诊断健康结果。

---

## C. 识别等待与“不做任何准备”不同

例如：

```
等待3个月
+
build savings
+
apply to jobs
```

属于：

```
ACTIVE PREPARATION
```

而不是纯 Inaction。

---

## D. 识别现状可能持续关闭未来选择

例如：

```
application deadline approaches
```

而用户：

```
does nothing
```

则：

```
option may expire
```

---

## E. 识别“不行动”也可能是成熟选择

如果：

```
risk low
current structure stable
information expected soon
```

则维持现状可以保留高资格。

---

# 12. `forbiddenInference`

NAV-05 严禁：

## A. 把不行动自动解释成逃避

禁止：

```
你没行动
→ 你在逃避
```

需要更多证据。

---

## B. 把行动自动解释成更成熟

禁止：

```
doing something
>
doing nothing
```

不存在这种默认排序。

---

## C. 把所有维持成本都夸大成恶化

例如：

```
工作有压力
```

不等于：

```
continuation is harmful
```

---

## D. 从 symbolic reading 推断“不行动会出事”

禁止：

```
Tarot Tower
→ waiting is dangerous
```

---

## E. 把机会成本伪装成确定损失

例如：

```
如果不辞职，你一定错过更好工作
```

不允许。

只能：

```
remaining in current role may reduce time available for external search
```

如果现实上成立。

---

## F. 把心理不适自动升级成 action trigger

不适可以进入 Current Reality；

但是否需要行动由后续 modules 判断。

# 14. `decisionThresholdEffect`

原则：

> **如果不行动本身会快速增加不可逆成本，行动所需的充分程度可能需要重新平衡；但这不等于降低安全、证据或责任边界。**

例如：

```
immediate safety risk
```

可能提高行动紧迫性；

但仍不能：

```
invent certainty
```

相反：

如果：

```
inaction cost low
option space preserved
```

则系统可以容忍更长观察期。

---

# 15. `authorityBoundary`

NAV-05 可以：

- 描述当前路径如何继续；
- 标示 continuation cost；
- 标示 option decay；
- 区分 monitoring 与 passive delay；
- 比较 action / inaction 的现实后果；
- 设定 review triggers。

NAV-05 不可以：

- 给不行动贴道德标签；
- 自动推动客户采取行动；
- 夸大未来损失；
- 用 symbolic prediction 建立风险；
- 把任何“不舒服”自动升级成必须改变。

应修正为：

# 28. Active Monitoring Rule

如果用户选择：

```

```

Navigation 应尽可能建立：

```
what to observe
until when
what would change the decision
```

例如：

```
Continue for 6 weeks

Observe:
work hours
sleep
monthly cash surplus
job-search responses

Reopen if:
sleep < threshold for 2 weeks
cash surplus turns negative
credible offer arrives
```

具体 threshold 必须来自用户/专业/现实资料，不能由系统随意发明。

# 29. Deferred Decision Rule

如果用户只是：

```

```

但没有：

```

review point
preparation plan
```

系统可以标记：

```
DEFERRED_DECISION
```

并提示：

> 目前等待的结束条件还没有被定义。

不能说：

> 你在拖延。

# 30. Maintenance Qualification Rule

“继续原样”必须回答：

```
why does continuation still qualify?
```

至少可从：

```
current value
acceptable cost
preserved options
low disruption risk
expected information gain
```

获得资格。

不能只因为：

```
we have always done this
```

获得资格。

---

# 31. Inaction Cost Rule

如果可量化：

允许计算。

例如：

```
monthly deficit = RM1,500
```

则：

```
6 months unchanged
= RM9,000 projected depletion
```

但必须显示：

```
assuming deficit remains unchanged
```

不能包装成确定未来。

---

# 32. Option Decay Rule

如果等待会让选项减少：

例如：

```

```

则 Inaction path 必须明确：

```
maintaining current state beyond 4 weeks

```

> 暂时继续当前工作并不是“没有决定”。它意味着收入继续、现有职责继续，而你目前的工作节奏也会继续存在。按照现在的现金流，维持六周可能让你进一步增加缓冲；但工作负荷是否会继续影响恢复，目前还不能确定，因此这部分需要继续观察。
> 
> 如果你选择暂时维持现状，最好把这六周当成一个有边界的观察期，而不是无限延后：到期后重新检查工时、恢复、现金缓冲和外部机会，再决定是否继续。

# 37. Canonical Runtime Rule

> **Navigation must treat continuation without new action as a real path whenever the current system will keep producing consequences over time.**

中文：

> **只要当前系统会继续随时间产生后果，Navigation 就必须把“不采取新动作而继续”视为一条真实路径。**

---

# 38. Canonical Neutrality Rule

> **Inaction is not neutral, but it is not inherently wrong. Its qualification depends on what continuation preserves, costs, closes, or allows.**

中文：

> **不行动并不中立，却也不是天然错误；它是否值得继续，取决于这种延续正在保留什么、支付什么、关闭什么，以及仍允许什么。**

---

# 39. Canonical Responsibility Rule

> **A person may choose not to act; Navigation must still make the foreseeable consequences of continuation visible without turning them into moral pressure.**

中文：

> **人可以选择不行动；Navigation 仍应让可合理预见的延续后果变得可见，却不能把这些后果变成道德施压。**
