# 5. `definition`

**Reversibility** 是 Navigation 对“一个行动进入现实以后，还能不能撤回、修正、缩小、恢复或转向”的正式判断。

它不是简单的：

```
YES / NO
```

也不是：

```
risk high / risk low
```

而是要回答：

> **如果这个决定后来被现实证明不合适，我们还有多少机会回来，又需要付出多大代价才能回来？**

一个行动即使表面相同，其真正的风险也会因为可逆性不同而完全改变。

例如：

```
尝试一门短期课程
```

通常具有较高可逆性；

而：

```
辞去唯一收入来源
出售主要住所
签署长期债务
进行不可逆医疗程序
作出重大法律承诺
```

则可能具有较低可逆性。

因此：

> **NAV-06 不判断一个选择是否值得，而是判断“做错以后还能怎样修正”，并据此调整后续 Decision Sufficiency 的门槛。**

---

# 6. `navigationMeaning`

可逆性决定 Navigation 能允许多少未知继续存在。

当行动：

```
highly reversible
```

Navigation 可以容许：

- 信息仍不完整；
- 先做小范围实验；
- 通过行动获取反馈；
- 较低成本地停止或修正。

当行动：

```
low reversibility
```

Navigation 必须提高：

- 证据要求；
- 准备要求；
- 专业核验；
- consent；
- contingency planning；
- downstream consequence review。

因此 NAV-06 的核心逻辑是：

```
Reversibility High
→ Reality can help us learn after acting

Reversibility Low
→ More must be understood before acting
```

但这不等于：

```
reversible = safe
irreversible = bad
```

只是决策结构不同。

# 10. Core Reversibility Classes

建议至少区分：

```
HIGHLY_REVERSIBLE
REVERSIBLE_WITH_COST
PARTIALLY_REVERSIBLE
LOW_REVERSIBILITY
EFFECTIVELY_IRREVERSIBLE
REVERSIBILITY_UNKNOWN
```

---

## A. `HIGHLY_REVERSIBLE`

行动可以较容易停止或撤回，而且：

```
exit cost low
residual consequence low
future options largely preserved
```

例如：

```
短期试课
小规模试点
限时项目
非排他性探索
```

---

## B. `REVERSIBLE_WITH_COST`

可以退出，但需要支付明确成本。

例如：

```
提前结束租约
结束某些服务合同
退出一个已开始的小型项目
```

---

## C. `PARTIALLY_REVERSIBLE`

可以改变一部分，但无法恢复原状。

例如：

```
搬迁后再搬回
```

地点可以恢复，但：

- 时间；
- 搬迁成本；
- 学校变化；
- 工作变化；

未必能完全恢复。

---

## D. `LOW_REVERSIBILITY`

退出虽然理论可行，但：

```
cost high
recovery long
future options materially changed
```

例如：

```
大规模资本投入
长期职业退出
高度绑定的合作结构
```

---

## E. `EFFECTIVELY_IRREVERSIBLE`

在当前导航范围内，行动一旦发生，不应假设可以恢复。

例如：

```
不可逆法律行为
某些医疗程序
公开披露无法收回的信息
某些已执行资产转移
```

具体判断需要合法 authority。

---

## F. `REVERSIBILITY_UNKNOWN`

系统不知道能否退出或恢复。

例如：

```
合同退出条款未读
退款权利未知
许可恢复条件未知
```

必须先确认。

# 12. `allowedInference`

NAV-06 可以：

## A. 判断一个方案是否可以通过小范围试验降低风险

例如：

```
full career switch
```

可能拆成：

```
course
freelance test
part-time experiment
internal project
```

这不是自动推荐，而是识别：

```
MORE_REVERSIBLE_VARIANT_EXISTS
```

---

## B. 识别退出成本

例如：

```
lease break penalty
```

可以进入：

```
REVERSIBLE_WITH_COST
```

---

## C. 识别“能恢复”与“能回到原样”不同

例如：

```
relationship pause
```

即使后来继续，也不代表：

```
original relationship state restored
```

---

## D. 识别时间会降低可逆性

例如：

```
pilot project
```

在早期可以轻易退出；

但随着：

```
more capital
more staff
more contracts
```

进入后，可逆性可能下降。

---

## E. 识别行动可以被重新设计成更可逆

例如：

```
buy
→ rent first

quit
→ leave / reduced hours / internal transfer first

full rollout
→ pilot
```

只允许作为候选结构，不得自动替用户选择。

---

# 13. `forbiddenInference`

NAV-06 严禁：

## A. 把“可逆”当成“无风险”

例如：

```
可以退出
```

不等于：

```
没有损失
```

---

## B. 把“不可逆”当成“不能做”

某些重要决定天然不可逆。

Navigation 只能：

```
raise threshold
```

不能：

```
ban action
```

除非另有合法 safety / professional authority。

---

## C. 用 Profile 判断客观可逆性

禁止：

```
你适应性强
→ 这项决定容易恢复
```

---

## D. 用 Method Reading 判断退出路径

禁止：

```
八字显示以后会有机会
→ 离职可逆
```

---

## E. 用 Tarot / I Ching 判断损失会不会恢复

禁止：

```
牌面显示转机
→ 资金风险可恢复
```

---

## F. 把理论上存在出口当成现实可退出

例如：

```
理论可以卖掉资产
```

不等于：

```
asset liquidation is currently feasible
```

# 15. `decisionThresholdEffect`

核心冻结关系：

```
higher reversibility
→ lower required decision sufficiency may be acceptable

lower reversibility
→ higher required decision sufficiency
```

但必须加入：

```
impact
responsibility
```

共同判断。

因此不能简单写成：

```
reversible = low threshold
```

真正逻辑：

```
Reversibility
×
Impact
×
Responsibility
×
Uncertainty
→ Required Decision Sufficiency
```

NAV-26 / NAV-27 最终处理完整门槛。

---

# 16. `authorityBoundary`

NAV-06 可以：

- 判断退出空间；
- 判断恢复难度；
- 标识残余后果；
- 比较大动作与可逆小动作；
- 调高后续 decision threshold；
- 标记需要专业核验的退出条件。

NAV-06 不可以：

- 宣布不可逆选择一定错误；
- 宣布可逆选择一定安全；
- 自动把大决定拆成小决定并执行；
- 用 symbolic system 建立现实恢复能力；
- 用未来想象当 exit plan。

---

# 17. `humanDecisionBoundary`

用户必须能够确认：

```
what loss they consider recoverable
what cost they are willing to bear
what state counts as acceptable recovery
```

例如：

一个人可能认为：

```
loss of RM5,000
```

可承受；

另一个人可能认为不可承受。

因此：

```
material reversibility
```

与：

```
personal tolerance
```

必须分开。

系统可以说：

> 这项行动在技术上可以撤回，但撤回需要承担约 RM5,000 成本。

不能直接说：

> 这是可逆的，所以风险低。

# 28. Exit Route Rule

任何重要行动，如果可以合法建立 exit route，Navigation 应显式保留：

```
EXIT_ROUTE
```

例如：

```
trial period
notice clause
stop-loss condition
pause point
rollback procedure
```

但：

> **存在退出路线，不等于退出路线现实可用。**

必须检查实际条件。

---

# 29. Recovery Rule

退出之后还必须问：

```
what state can realistically be recovered?
```

例如：

```
business closes
```

能恢复的可能是：

```
cash preservation
employment re-entry
operational stability
```

而不是：

```
all prior money and time
```

---

# 30. Residual Effect Rule

一个行动即使撤回，仍可能留下：

```
financial residue
relationship residue
legal residue
reputation residue
time loss
identity impact
```

因此：

```
rollback
≠
full restoration
```

---

# 31. Minimum Reversible Action Rule

当：

```
uncertainty high
```

且存在合法的较小行动时，Navigation 可以生成：

```
MORE_REVERSIBLE_VARIANT_AVAILABLE
```

例如：

```
full move
→ temporary stay first

full business launch
→ pilot

full resignation
→ internal transfer / leave / side test
```

但这只是候选，不是系统推荐。

```

```

# 34. Customer Projection Example

内部：

```
Option:
Quit immediately

Reversibility:
PARTIALLY_REVERSIBLE

Exit from action:
Can seek employment again

Residual effects:
income gap
benefit interruption
career transition cost

Recovery:
requires liquidity + job re-entry

Unknown:
re-entry time
```

客户可看到：

> **这个选择不是完全不可回头，但也不是按下撤销键就能恢复原状。**
> 
> 你以后仍然可以重新就业，因此它并非绝对不可逆；但收入中断、福利连续性、重新求职所需时间，以及职业路径变化都可能留下残余影响。换句话说，真正需要判断的不是“以后还能不能找工作”，而是“如果这次离开没有按预期发展，你是否有足够资源支撑恢复过程”。

# 38. Canonical Runtime Rule

> **Navigation must evaluate how much of an action can be undone, what cannot be restored, and what recovery would require before treating that action as decision-ready.**

中文：

> **Navigation 在把一个行动视为可进入决定以前，必须先判断其中多少能够撤回、什么无法恢复，以及如果判断错误，恢复需要什么条件。**

---

# 39. Canonical Threshold Rule

> **The less reversible an action is, the more decision sufficiency is required before action; reversibility does not eliminate the need to consider impact or responsibility.**

中文：

> **一个行动越难撤回，行动以前所需要的决策充分程度就越高；但可逆性本身并不能取代对影响与责任的判断。**

---

# 40. Canonical Experiment Rule

> **When uncertainty is high and a materially more reversible path exists, Navigation may expose the smaller path as an option for learning without treating it as the preferred answer.**

中文：

> **当未知较高，而现实中存在明显更可逆的小范围路径时，Navigation 可以把它作为获取现实反馈的候选，却不能因此把它自动设为首选答案。**

---

# 41. Canonical Restoration Rule

> **Reversal is not restoration. Returning from an action may stop further consequences without recovering everything that has already changed.**

中文：

> **撤回不等于恢复原状；停止一个行动，可以阻止后果继续扩大，却未必能够取回已经改变的部分。**

---

# 5. `definition`

**Time Horizon** 是 Navigation 对“一个决定究竟正在影响多远的未来”进行正式分层的机制。

它不是简单区分：

```
short term
medium term
long term
```

也不是要求客户优先考虑长期利益。

它真正回答的是：

> **这个决定会在什么时间尺度上产生价值、成本、锁定、责任与机会，而不同时间尺度之间是否正在互相冲突？**

例如：

```
接受更高薪但高强度的工作
```

可能在：

```
0–12 months
```

带来：

```
higher income
debt repayment
cash accumulation
```

但在：

```
3–5 years
```

可能同时影响：

```
health capacity
family time
skill development
career optionality
```

因此：

> **NAV-07 不寻找“最长远的答案”，而是阻止一个时间尺度上的收益偷偷代表所有未来。**

---

# 6. `navigationMeaning`

一个方案可能：

```
SHORT_TERM_STRONG
LONG_TERM_WEAK
```

也可能：

```
SHORT_TERM_COSTLY
LONG_TERM_CAPACITY_BUILDING
```

如果 Navigation 只看单一时间层，就很容易产生错误比较。

例如：

```
Option A:
立即增加收入

Option B:
暂时减少收入，建立新能力
```

如果只看：

```
next 3 months
```

# 5. `definition`

**Navigation Authority** 是 PHI OS 对“系统能够参与决定到什么程度”的正式边界。

它不是一般性的 AI disclaimer，也不是一句简单的：

```
最终决定由用户负责
```

而是要明确区分：

```
系统可以组织什么
系统可以比较什么
系统可以推断什么
系统可以建议到哪里
系统什么时候必须停止
系统什么时候必须升级给专业人士、共同决策者或真正拥有决定权的人
```

Navigation 可以：

- 建立 Decision Object；
- 重构 Current Position；
- 区分 Closed / Open Conditions；
- 比较时间与可逆性；
- 组织 options；
- 暴露 constraints；
- 显示 evidence / unknown；
- 比较 consequences；
- 提出更可逆的候选动作；
- 指出哪些信息会改变判断；
- 识别需要专业核验或共同同意的地方。

但它不能因为掌握：

```
更多数据
更多报告
更多模型
更强计算
更完整 Profile
更多历史
```

就自动取得：

```
LIFE_DECISION_OWNERSHIP
```

因此：

> **NAV-08 定义的不是系统“能不能给建议”，而是任何建议都必须停留在不夺走人类决定权的位置。**

---

# 6. `navigationMeaning`

前面的 NAV-01–07 已经让 Navigation 逐渐形成一个很强的能力：

```
知道正在决定什么
知道用户站在哪里
知道什么已关闭
知道什么仍开放
知道时间如何改变问题
知道不行动会发生什么
知道行动是否可逆
知道这个决定影响多远的未来
```

如果没有 NAV-08，这些能力越强，风险反而越大，因为系统很容易从：

```
better understanding
```

越界到：

```
decision substitution
```

例如：

```
Current Position shows low liquidity
+
Profile shows high autonomy need
+
BaZi shows timing pressure
+
Tarot shows transition
```

系统绝不能因此输出：

> “所以你应该辞职。”

真正合法的输出只能是：

> “当前离职路径的现实门槛较高；如果自主性仍是你想保护的价值，可以比较更可逆的路径，例如先建立替代收入、内部调岗或缩小现有负荷。”

也就是说：

> **Navigation 的作用是提高决定质量，不是取得决定所有权。**

# 10. Core Authority Classes

建议 runtime 至少区分：

```

SHARED_DECISION
PROFESSIONAL_ADVISORY
PROFESSIONAL_REQUIRED
REPRESENTATIVE_DECISION
INSTITUTIONAL_AUTHORITY
CONSENT_REQUIRED
NAVIGATION_SUPPORT_ONLY
AUTHORITY_UNKNOWN
```

---

## A. `USER_DECISION_OWNER`

决定主要属于用户本人。

例如：

```
职业方向
个人学习计划
个人生活节奏
非共同财务范围内的个人选择
```

系统可以帮助比较，但最终选择属于用户。

---

## B. `SHARED_DECISION`

决定影响多个拥有真实利益与权利的人。

例如：

```
家庭搬迁
共同资产
关系结构
共同育儿安排
公司合伙决策
```

系统不能把一个人的 preference 当成全部人的决定。

---

## C. `PROFESSIONAL_ADVISORY`

用户仍拥有最终决定权，但需要专业意见显著提高判断质量。

例如：

```
复杂财务规划
税务安排
某些法律安排
复杂职业转型
```

---

## D. `PROFESSIONAL_REQUIRED`

某些行动在进入现实以前必须经过有资格专业人士。

例如：

```
某些医疗程序
正式法律文件
受监管财务行为
专业签署
```

系统不得绕过。

---

## E. `REPRESENTATIVE_DECISION`

当本人无法完整表达或承担决定时：

```
minor
dependent
incapacitated person
```

可能需要合法代表。

Navigation 必须区分：

```
representing interests
≠
projecting hidden preference
```

---

## F. `INSTITUTIONAL_AUTHORITY`

组织、学校、公司、政府或制度可能拥有某些正式决定权。

就推定其拥有无限决定权。

# 5. `definition`

**Change Threshold** 是 Navigation 对“现实中的变化是否已经重要到足以重新打开决定”进行正式判断的机制。

它不回答：

> “现实有没有变化？”

因为现实几乎一直在变化。

它真正回答的是：

> **“这个变化是否已经触及原先决定赖以成立的条件，以至于原方向不能再被自动延续？”**

例如：

```
收入本月下降 5%
```

本身不一定触发重决策。

但如果同时发生：

```
收入下降
+
现金缓冲缩小
+
固定支出增加
+
工作稳定性降低
```

那么真正变化的已经不是一个单独数字，而是：

```
原先继续当前路径的现实基础
```

因此：

> **NAV-09 不是变化侦测器，而是“变化是否足以重新取得决策资格”的阈值判断。**

---

# 6. `navigationMeaning`

如果 Navigation 把所有变化都当作需要行动，会产生：

```
OVERREACTION
```

如果 Navigation 只在彻底失败时才承认变化，会产生：

```
LATE_REACTION
```

因此 NAV-09 必须区分：

```
change observed
≠
decision-relevant change
```

真正取得 Navigation 意义的变化，通常至少改变以下一种：

```
feasibility
cost
capacity
responsibility
risk
time window
reversibility
future option space
decision owner / consent
```

只有当变化触及这些条件之一，原 Decision State 才应被重新打开。

# 10. Core Change Classes

建议 runtime 至少区分：

```
NO_MATERIAL_CHANGE
LOCAL_CHANGE
PERSISTENT_CHANGE
CROSS_DOMAIN_CHANGE
FOUNDATIONAL_CHANGE
CHANGE_SIGNIFICANCE_UNKNOWN
```

---

## A. `NO_MATERIAL_CHANGE`

现实有波动，但没有改变决策条件。

例如：

```
单月小幅收入波动
短期工作忙碌
一次关系摩擦
```

如果：

```
resources stable
capacity stable
future options stable
```

则原决定可继续保持。

---

## B. `LOCAL_CHANGE`

变化只影响局部条件。

例如：

```
通勤时间增加
某一项目延期
某项费用上升
```

可能需要局部回应，但不一定重新打开整个决定。

---

## C. `PERSISTENT_CHANGE`

变化不再是一次性波动，而持续存在。

例如：

```
连续4个月现金流恶化
长期工作时数增加
重复出现的交付失败
```

这种状态提高重决策权重。

---

## D. `CROSS_DOMAIN_CHANGE`

变化开始影响多个重要领域。

例如：

```
workload
→ sleep
→ family interaction
→ financial spending
```

这与后续 NAV-14 直接相关。

---

## E. `FOUNDATIONAL_CHANGE`

变化直接改变原先 Decision Basis。

例如：

```
job security lost
new dependant
major debt
legal status changed
partner consent withdrawn
critical capacity reduced
```

这类变化应触发：

```
DECISION_REOPEN
```

---

# 11. `allowedInference`

NAV-09 可以：

## A. 比较新现实与原 Decision Basis

例如：

```
Original basis:
salary stable

Current:
salary materially reduced
```

可以标记：

```
FOUNDATIONAL_CHANGE
```

---

## B. 识别一个变化是否持续到足以失去“只是波动”的资格

例如：

```
1 week overload
```

与：

```
6 months overload
```

不应同等处理。

---

## C. 识别多个小变化组合后产生更大意义

例如：

```
small income drop
+
small cost increase
+
small debt increase
```

单项都不大，但组合后可能改变 liquidity。

---

## D. 识别一个变化是否改变 option eligibility

例如：

```
visa eligibility changed
```

可能直接改变迁移选项。

---

## E. 识别变化是否只是表面指标变动

例如：

```
title changed
```

但：

```
responsibility
income
authority
workload
```

不变，则 decision relevance 可能较低。

---

# 12. `forbiddenInference`

NAV-09 严禁：

## A. 把变化强度直接等同决策重要性

大变化可能是短期波动。

小变化可能触及关键边界。

---

## B. 用 symbolic timing 证明现实已变化

禁止：

```
八字进入新大运
→现实条件已改变
```

除非 Current Reality 独立支持。

---

## C. 把用户情绪变化自动写成系统条件改变

情绪重要，但必须区分：

```
felt change
vs
material change
```

---

## D. 把一次异常直接升级成新结构

禁止：

```
one bad month
→ financial structure broken
```

---

## E. 把变化存在直接变成行动命令

```
change detected
≠
change required
```

# 13. `decisionEffect`

NAV-09 主要影响：

```

```

它的核心作用不是选方向，而是：

> **决定原来的判断是否仍有资格继续被沿用。**

---

# 14. `decisionThresholdEffect`

如果变化：

```
FOUNDATIONAL_CHANGE
```

则原先的 Decision Sufficiency 不应自动继承。

必须：

```
reassess current position
reassess option space
reassess threshold
```

原则：

> **A decision that was sufficient under one reality state does not remain sufficient after its material basis changes.**

中文：

> **一个决定在旧现实下曾经充分，并不代表在决定基础发生实质变化以后仍然充分。**

---

# 15. `authorityBoundary`

NAV-09 可以：

- 识别变化；
- 判断变化是否触及 Decision Basis；
- 重开 Navigation；
- 标记局部变化；
- 标记 persistent / foundational change；
- 要求更新 Current Position。

NAV-09 不可以：

- 仅凭变化就建议彻底改变；
- 把短期波动夸大；
- 用方法解释证明现实变化；
- 把新状态自动升级成危机。

---

# 16. `humanDecisionBoundary`

用户必须能够修正：

```
what changed
when
how much
whether it matters
```

例如系统认为：

```
收入下降
```

> **真正变化的并不是收入，而是维持这份工作的现实条件。**

> **A change becomes navigation-relevant when it materially alters the conditions under which the current decision remained qualified.**

中文：

> **稳定并不是没有变化，而是在变化发生以后，当前路径仍然能够重新取得继续资格。**

## 3. `canonicalTitleEn`

```
Response Level
```

## 4. `canonicalQuestion`

```
为什么发现问题以后，不是只有继续忍耐与彻底改变两个选择？
```

# 5. `definition`

**Response Level** 是 Navigation 对“现实已经取得决策意义之后，应该以多大尺度回应”进行正式分层的机制。

它不是：

```
ACT / DO NOTHING
```

这种二元选择，也不是把任何变化都直接升级成：

```
LEAVE
STOP
RESTRUCTURE
END
```

它真正回答的是：

> **当前变化究竟需要注意、监测、准备、局部调整，还是已经达到结构性回应的程度？**

现实问题有不同深度。

例如：

```
一次短期工作高峰
```

可能只需要：

```
MONITOR
```

而：

```
长期工作负荷上升
+
恢复下降
+
家庭安排持续受影响
```

可能需要：

```
LOCAL_ADJUSTMENT
```

甚至：

```
STRUCTURAL_RESPONSE
```

因此：

> **NAV-10 的作用不是决定“改不改变”，而是让回应尺度与现实问题尺度相匹配。**

---

# 6. `navigationMeaning`

如果系统没有 Response Level，Navigation 很容易出现两种极端。

第一种：

```
UNDER_RESPONSE
```

现实已经明显改变，却因为“还没彻底坏掉”而继续维持。

第二种：

```
OVER_RESPONSE
```

一个局部、暂时、可恢复的问题，被立刻升级成全面改变。

因此 NAV-10 建立的是：

```
Observed Problem
↓
Decision-Relevant Change
↓
Response Scale
```

而不是：

```
Problem
↓
Maximum Action
```

成熟 Navigation 应该能够说：

> 现在需要回应，但不一定需要最大回应。

# 10. Core Response Levels

建议 runtime 至少区分六级：

```
R0_OBSERVE
R1_MONITOR
R2_PREPARE
R3_LOCAL_ADJUST
R4_STRUCTURAL_CHANGE_CANDIDATE
R5_IMMEDIATE_ESCALATION
```

---

## A. `R0_OBSERVE`

变化已被看见，但：

```
decision relevance low
impact limited
persistence not established
```

当前动作：

```
observe only
```

例如：

```
一次短期收入波动
一次沟通摩擦
短暂工作高峰
```

---

## B. `R1_MONITOR`

变化值得持续追踪，但尚不足以改变结构。

必须定义：

```
what to observe
review interval
trigger conditions
```

例如：

```
连续观察3个月现金流
连续记录睡眠与工作时长
```

---

## C. `R2_PREPARE`

现实已经足以让系统为改变做准备，但尚未要求真正实施重大变化。

例如：

```
更新履历
增加现金缓冲
搜集学校资料
确认合同
了解替代方案
```

这一级很重要，因为它让 Navigation 不必等到危机才开始行动。

---

## D. `R3_LOCAL_ADJUST`

需要直接改变当前运行中的局部参数。

例如：

```
减少某项负荷
重新分配预算
调整工作边界
改变会议频率
重新分工
```

目标是：

```
restore fit
without redesigning entire structure
```

---

## E. `R4_STRUCTURAL_CHANGE_CANDIDATE`

局部回应持续不足，或原结构已经无法通过参数调整重新适配现实。

这时可以把：

```
alternative structure
```

正式放进候选。

注意：

```
CANDIDATE
```

不等于：

```
EXECUTE
```

---

## F. `R5_IMMEDIATE_ESCALATION`

当存在：

```
safety risk
critical legal issue
acute financial failure
professional requirement
high-impact rapidly closing window
```

时，系统需要立即升级给：

```
qualified human authority
professional support
emergency process
```

而不是自己继续普通导航。

---

# 11. `allowedInference`

NAV-10 可以：

## A. 根据持续性提高回应等级

例如：

```
one-week overload
```

与：

```
six-month overload
```

不应使用同一级回应。

---

## B. 根据跨领域影响升级回应

例如：

```
work issue
→ sleep
→ family
→ finances
```

可提高 Response Level。

---

## C. 根据已有回应失效升级

例如：

```
R1_MONITOR
↓
R3_LOCAL_ADJUST
↓
problem persists
```

可以考虑：

```
R4_STRUCTURAL_CHANGE_CANDIDATE
```

---

## D. 根据现实改善降级

回应不是只能升级。

例如：

```
local adjustment effective
```

可以从：

```
R3
```

降回：

```
R1
```

---

## E. 识别准备本身就是有效回应

例如：

```
还未辞职
但已经增加现金缓冲、更新技能、建立替代路径
```

这不是“什么都没做”。

应识别为：

```
R2_PREPARE
```

---

# 12. `forbiddenInference`

NAV-10 严禁：

## A. 把“回应等级高”理解成“问题一定严重”

Response Level 是行动尺度，不是诊断标签。

---

## B. 把第一次失败就升级成结构性改变

局部调整失败一次，不足以自动：

```
R4
```

---

## C. 用 symbolic reading 决定回应等级

禁止：

```
Tarot Tower
→ R4
```

---

## D. 把客户情绪强度直接映射成行动强度

```
feels terrible
≠
maximum structural response
```

除非现实证据支持。

---

## E. 把准备误写成最终决定

```
prepare to leave
≠
decision to leave
```

---

## F. 把专业升级误写成系统自己下结论

```
R5
```

通常意味着：

```
handoff
```

而不是系统继续输出更强建议。

# 14. `decisionThresholdEffect`

原则：

> **回应越大、越不可逆、影响越广，所需 Decision Sufficiency 越高。**

例如：

```
R1_MONITOR
```

通常需要较低 threshold。

```
R4_STRUCTURAL_CHANGE_CANDIDATE
```

需要更高 threshold。

```
R5_IMMEDIATE_ESCALATION
```

不是“降低 threshold”，而是：

```
change authority path
```

把问题交给更适当的人或程序。

---

# 15. `authorityBoundary`

NAV-10 可以：

- 划分回应等级；
- 建议观察；
- 建议准备；
- 建议局部调整；
- 将结构性变化放入候选；
- 建议专业升级；
- 根据现实结果升降级。

NAV-10 不可以：

- 自动执行结构性变化；
- 自动终止关系／工作／合同；
- 用 symbolic interpretation 决定行动等级；
- 把更强回应包装成更“勇敢”；
- 把低级回应包装成逃避。

# 16. `humanDecisionBoundary`

用户必须能够：

```

choose lower level
choose higher level
request professional review
revise action scale
```

例如系统建议：

```

```

用户可以说：

> 我只想先观察。

系统应保留风险与 trade-off，但不能强制升级。

高风险安全场景除外，应按 NAV-08 authority / professional rule 处理。

# 29. Preparation Rule

`R2_PREPARE` 必须是真实准备，不是模糊焦虑。

```
review point

```

```
confirm contract terms

```

不能只写：

```

```

`R3_LOCAL_ADJUST` 应尽量限定：

```

duration
expected effect
review trigger

```

```
for 6 weeks

```

不得无期限。

# 31. Structural Candidate Rule

`R4_STRUCTURAL_CHANGE_CANDIDATE` 只意味着：

> 原结构不再享有唯一默认资格。

它不意味着：

```
must restructure
```

后续仍需 NAV-17 等模块进一步判断。

---

# 32. Immediate Escalation Rule

`R5_IMMEDIATE_ESCALATION` 应优先输出：

```
who to contact
what domain authority is needed
what action should pause
what information should be preserved
```

而不是生成更多普通建议。

---

# 33. Customer Projection Example

内部：

```
Change:
persistent workload increase

Current response history:
monitoring for 8 weeks
minor schedule adjustment failed

Response level:
R3_LOCAL_ADJUST

Potential escalation:
R4 if workload remains unchanged after review
```

客户可以看到：

> **现在已经不只是“再观察一下”的阶段。**
> 
> 过去八周你已经持续记录工作时长，并尝试过局部排程调整，但负荷没有明显下降；这使回应可以从单纯监测提高到局部调整，例如重新谈职责、减少部分工作范围，或改变当前分配方式。
> 
> 这还不足以自动推出“必须离开”，但如果局部调整之后现实仍然没有改善，就需要把另一种工作结构正式放进候选。

# 37. Canonical Runtime Rule

> **Navigation must scale the response to the decision-relevant change rather than forcing a binary choice between endurance and total change.**

中文：

> **Navigation 必须让回应尺度与具有决策意义的变化相匹配，而不是把用户逼进“继续忍耐”与“彻底改变”的二选一。**

---

# 38. Canonical Proportionality Rule

> **The smallest response capable of materially improving the situation should remain visible before larger and less reversible responses are treated as necessary.**

中文：

> **在更大、更难撤回的回应被视为必要以前，能够实质改善现实的较小回应必须先保持可见。**

这不是强制先做小动作，而是防止大动作过早取得默认资格。

---

# 39. Canonical Escalation Rule

> **Response level may increase when persistence, spread, failed lower-level responses, shrinking option space, or high-impact risk materially changes what the current path can still absorb.**

中文：

> **当问题持续、扩散、较低等级回应持续失效、选择空间收窄，或高影响风险已经改变当前路径的承受能力时，回应等级可以上升。**

---

# 40. Canonical De-escalation Rule

> **Navigation must be able to reduce response intensity when reality improves; escalation is not a one-way status.**

中文：

> **当现实改善时，Navigation 必须能够降低回应强度；升级不是单向状态。**

---
