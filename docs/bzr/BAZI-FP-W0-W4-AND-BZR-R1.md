# BaZi Full Production｜W0–W4 + BZR-R1

Baseline: `14b6735b1ffb804c160b0b5306646994ee1ab1dd`

This successor work starts the BaZi Full Production program without rewriting the existing BZR v1 or BZT v2 freezes.

## W0｜Current Authority Audit

The current repository already has deterministic true-solar-time Four Pillars, exact Li Chun/Jie boundaries, three/four-pillar degradation, Luck Cycle sequence, a bounded production projection, 27 shallow canonical-meaning mappings, and a temporal successor with current Luck Cycle plus annual context.

The main customer-depth gap is not calendar calculation. The current interpretation path composes one near-identical unit for each Year/Month/Day/Hour Pillar from shallow STEM/BRANCH/PILLAR meanings. It does not yet calculate the chart-level evidence needed for roots, governed strength, relations, Ten Gods, patterns, useful-god/tiaohou or natal × Da Yun × Liu Nian interpretation.

## BZR-R1｜Source Strategy

Source order is frozen as:

1. Tier 1 — public-domain classical sources: 《三命通会》, 《子平真诠》, 《滴天髓》.
2. Tier 2 — public academic/digital witnesses for edition, locator and scan/transcription comparison.
3. Tier 3 — modern public professional material for coverage and modern-explanation comparison only.
4. Tier 4 — commercial books only after a named gap remains.

Metadata registration is not rule authority. The three classical works are registered, but production rule-claim count remains zero until source claims are extracted, located to a witness and human-reviewed for source fidelity. Underlying public-domain status and digital-witness rights are tracked separately.

## W1｜Canonical BaZi Chart Contract

`bazi-chart-runtime.js` consumes the existing Canonical Method Projection and creates a derived BaZi Chart IR. It is explicitly **not** a second projection authority. It supplies localized stem/branch identities, element/polarity, hidden-stem structural mappings, Day Master, Month Command, visible/hidden element inventories, unknowns and lineage.

## W2｜Strength & Seasonal Runtime

The first runtime is intentionally evidence-only. It exposes Month Command/season, Day Master relation to the month element, root evidence and visible element relations. It does **not** emit `strong/weak`, numerical strength scores or Useful God before a versioned source-admitted strength model exists.

## W3｜Stem / Branch Relationship Engine

The structural engine detects registered stem combinations, branch six-combinations, clashes, harms, breaks, full three-harmony/full three-meeting groups, conservative punishment groups and self-punishment duplication. Presence of a relation is not treated as successful transformation, good/bad score, event prediction or a customer conclusion.

## W4｜Ten-God Structural Runtime

Ten Gods are now deterministically classified for visible stems and hidden stems against the Day Master. The Day Stem is presented as Day Master, not as a customer Ten-God label. Counts are unweighted. No personality, wealth, career, relationship or fate meaning is created at this stage.

## Stop point

W5 Pattern / 格局 and W6 调候 / 用神 must not be opened by invented rules. The next legitimate work is BZR-R1 source-claim extraction and admission, then W5. W7/W8 can reuse the existing Luck Cycle and annual temporal authority, but their **interpretation interaction** must also wait for admitted structural rules.
