# Method Runtime Layers

## Frozen order

| Order | Layer | Input | Output | Core prohibition |
| ---: | --- | --- | --- | --- |
| 1 | Method Definition | IMR evidence | Versioned Method Definition | Runtime must not invent a Method |
| 2 | Data Authority | Verified source data | Normalized shared data | No method-owned duplicate authority |
| 3 | Calculation Runtime | Definition plus normalized data | Repeatable calculation facts | No Provider, Prompt or Interpretation |
| 4 | Projection Runtime | Calculation facts | Projection JSON | No Interpretation or Professional authority |
| 5 | Interpretation Runtime | Projection, Published Knowledge, optional Journey context | Interpretation Candidate | No automatic Professional Conclusion |
| 6 | Professional Runtime | Governed candidate plus evidence | Reviewed and released deliverable | No non-independent review or unsigned release |

No active layer may be bypassed or reordered.

## Method Definition

An IMR-approved definition fixes scope, algorithm, data authority, license, commercial rights, version and Production Eligibility. Runtime execution cannot precede it.

## Data Authority

Shared Data Authority owns Birth Record, Coordinate, Timezone, DST, True Solar Time, Astronomy, Calendar, Solar Terms and Reference Tables. These resources do not belong to HDR, AST, BZR or any other Plugin.

## Calculation Runtime

Calculation is 100% repeatable. It uses a deterministic engine or a verified external calculation engine. The following are prohibited:

- OpenAI
- Workers AI
- Prompt-based calculation
- Interpretive inference
- Fabricated missing data

A method engine may have its own code and version, but executes within Shared Calculation Runtime.

## Projection Runtime

Projection Runtime emits versioned Projection JSON. Examples include Gate, Authority, Planet, Stem, Hexagram, Card and Profile. Projection preserves facts and structure; it contains no Interpretation and creates no Professional authority.

## Interpretation Runtime

Interpretation Runtime may use Rule Engine, Workers AI or OpenAI. Inputs are governed Projection, Published Knowledge and optional Journey context. Output is always INTERPRETATION_CANDIDATE.

## Professional Runtime

Professional Runtime independently performs Professional Review, Boundary Validation, Deliverable Assembly, Professional Signature and Release. The authorized human remains responsible. Professional Runtime is distinct from Professional Workspace; the Workspace is the downstream operating surface.
