# REL-W4 方法覆盖审计

当前 REL-W4 已经建立可治理的 method-specific relationship composition 框架，但它还不是完整的 PHI OS Relationship 产品。

AST 已有跨人 major-aspect structural projection，因此可以保留「A 的某个功能与 B 的某个功能形成受治理结构接触」；现阶段不把 natal aspect meaning 直接升级为 synastry meaning。NUM 已有 D8 Human-admitted multi-factor structure，因此可进入 REL-W4，但 Relationship Number 的计算获准并不等于其关系含义获准。

BaZi 的现有 `bazi-relationship-runtime.js` 是单一 natal chart 内四柱之间的 stem/branch 关系检测器。它很适合成为未来 A×B detector 的技术基础，因为 relation presence、无 transformation verdict、无 good/bad conclusion 等边界已经存在；但现有 authority 不能直接把 chart-internal relation 改名成 pair meaning。需要新的 participant-tagged cross-person scope、来源策略、关系专属 semantic corpus 与 Human admission。

Zi Wei 不建议为了追求“合盘感”直接发明 cross-chart star relocation。当前专业层已经有 RELATIONSHIPS topic，并具有 `coreStructure / entryPattern / interactionPatterns / stabilityConditions / pressurePositions / currentTiming / realityCheck` 等结构。更稳的关系 successor 是让 A 与 B 各自的 accepted relationship-domain semantics 保持独立，再用获准的 comparison rules 组合「两套关系结构相遇时」的共同点、差异、互补条件、压力位置和 timing context。只有未来选择明确学派并完成来源治理时，才考虑另开 cross-chart mechanics。

ECR 应该成为 PHI OS 最有辨识度的关系层，而不是模仿八字、占星或 MBTI 的 compatibility。ECR 已有 CC / G / Q / R / D / M / H / A canonical coordinates 与 Q→R capability matrix，因此适合建立 directed pair graph：A 的 Question 如何遇到 B 的 Capability、B 的 Question 如何遇到 A 的 Capability；A 的 environment-priority 如何与 B 的 embodied-response position 形成方向性边；Driver、Motion、Activation 保留为上下文差异，而不是自动判断好坏。第一阶段只建立 neutral structural relations；任何 support / complement / tension / asymmetry / misread-risk 都必须来自 PHI OS 自己版本化、可审查、Human-admitted 的 pair rule corpus。

因此，当前系统在 REL-W4 Human admission 后可以继续 REL-W5–W8，并形成一个 AST + NUM 的有限版 relationship product；但若目标是“PHI OS 多方法完整 Relationship”，建议在正式 cutover 前补齐 BZR、ZWR、ECR 三条 relationship successor authority。HD 双图关系可继续 optional fail-closed，不必阻塞第一版。
