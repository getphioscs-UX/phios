# PHI OS Editorial Style Bible

PHI OS 中文文章采用出版书籍式的自然论述。正文应以完整的机制发展为中心，通过较长但清晰的段落维持思想连续性，允许逗号、分号与必要的短句共同形成节奏；不得把中文写成逐句翻译的英文结构，也不得依靠连续短句制造虚假的力量感。

文章必须同时保持哲学视野与系统论边界。理论解释应明确属于 PHI OS 框架，外部事实必须绑定合法来源，两者不能互相伪装。类比与例子只帮助理解，不能代替证据，不能创造新的 Claim，也不能扩大 Canonical Boundary。

标题应指向真实问题、概念区分或运行机制，不使用统一营销模板。段落通常以 180–650 个中文字为宜；复杂机制可以更长，但不应超过 1000 字。项目符号只用于引用、边界或确实需要逐项核对的结构，不能替代正文发展。

文章不使用空泛总结，不以营销 CTA 结束，不默认推荐服务，不诊断读者，也不制造付费焦虑。结尾应完成一个边界、区分或连续关系，使读者自然进入下一个 Canonical Question。

禁用或重点审查的表达包括：“在当今快速发展的时代”“值得注意的是”“从某种意义上说”“总而言之”“让我们一起”“赋能”“颠覆”，以及反复使用“这不仅是……更是……”的模板句式。禁用库由 `phi-os-editorial-style.json` 统一维护，不散落在 checker 中。

`draft.md` 是 TL 唯一直接编辑的正文文件。Node Code、Claim Code、Source Code、Blocking Code、内部路径、Hash、Review Status 与 Production Status 只能存在于治理文件，不能出现在面向读者的正文。
