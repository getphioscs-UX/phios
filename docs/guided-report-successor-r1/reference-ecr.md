# ECR-02｜什么是 PHI 构型？
## WHAT IS PHI CONFIGURATION?

### 页面角色
`METHOD_INTRODUCTION`

### 固定标题

**什么是 PHI 构型？**  
**WHAT IS PHI CONFIGURATION?**

### 固定副标题

**把一个人的运行结构整理成问题、能力、驱动、运动、构型与激活阶段。**

**A structured reading of question, capability, driver, motion, configuration, and activation.**

### 中文固定正文

PHI 构型是 PHI OS 内部建立的一套个人运行结构读取方法。它不把一个人压缩成单一人格类型，而是把不同运行维度放在同一套结构中观察，包括核心问题、能力区域、驱动优先级、运动模式、构型关系与激活阶段。

这些维度并不是彼此独立的标签。它们共同描述的是：一个人的基线结构更容易围绕什么问题组织，可用能力分布在哪里，哪些驱动更容易取得优先位置，结构如何运动与变化，以及当前构型处在怎样的激活位置。

PHI 构型首先提供的是一张结构图，而不是现实本身。它可以帮助客户观察自己的运行模式与变化位置，但不能仅凭出生结构或单一构型就证明一个人的当前行为、情绪、健康状态或未来结果。

### Fixed English Copy

PHI Configuration is a first-party PHI OS method for reading personal runtime structure. It does not reduce a person to a single personality type. Instead, it organizes multiple runtime dimensions within one structural framework, including Core Question, Capability Region, Driver Priority, Motion, Configuration, and Activation.

These dimensions are not isolated labels. Together they describe how a baseline runtime may be organized: what kind of question receives structural emphasis, where capability is concentrated, which drivers receive priority, how the configuration moves or changes, and where it sits within an activation stage.

PHI Configuration first provides a structural map rather than a statement of Reality itself. It can help a customer observe runtime patterns and change, but birth structure or configuration alone cannot establish present behavior, emotional state, health condition, or future outcome.

# ECR-03｜为什么 PHI OS 要建立 PHI 构型？
## WHY WAS PHI CONFIGURATION BUILT?

这页不是“历史传承”，而是 **方法发展页**。

### 页面角色
`METHOD_ORIGIN_CONTINUITY`

### 固定副标题

**因为个人运行并不只表现为人格特征，还涉及结构、驱动、变化、环境与当前现实之间的关系。**

**Because personal runtime cannot be reduced to personality traits alone; it also involves structure, drivers, motion, context, and current Reality.**

### 中文固定正文

PHI 构型之所以被建立，是因为 PHI OS 在处理个人读取时遇到一个反复出现的问题：传统方法和人格工具往往能够提供大量标签与解释，却不一定能够清楚回答“这个结构当前怎样运行”“哪些部分只是基线”“哪些部分受到环境与现实条件改变”。

因此，PHI 构型并不是为了再增加一个人格分类系统，而是为了建立一套更接近运行语言的结构。它把核心问题、能力、驱动、运动、构型与激活放在同一个框架中，使个人结果可以进一步与载体条件、经验表达与当前现实比较，而不是在出生结果生成后就停止。

这个方法仍然处在受治理、可修订的体系中。新的解释必须有来源、映射规则与证据，不能因为结构看起来合理，就自动变成关于客户现实的事实。

### Fixed English Copy

PHI Configuration was developed because PHI OS repeatedly encountered a limitation in personal reading: traditional systems and personality tools can produce many labels and interpretations without clearly distinguishing how a structure is currently operating, which parts belong only to a baseline, and which parts may change under environmental or real-world conditions.

PHI Configuration was therefore not built to add another personality classification system. It was designed as a runtime-oriented structure that places Core Question, Capability, Driver, Motion, Configuration, and Activation within one framework. This allows a personal result to be compared later with carrier conditions, experience expression, and current Reality rather than ending at the birth-based projection.

The method remains governed and revisable. New interpretations require source lineage, admitted mapping rules, and evidence. A structurally plausible idea does not automatically become a fact about the customer.

# ECR-04｜PHI OS 如何看待并使用 PHI 构型？
## HOW DOES PHI OS USE PHI CONFIGURATION?

### 页面角色
`PHIOS_METHOD_LENS`

### 固定副标题

**保留基线构型，同时把结构、载体、经验与当前现实分开读取。**

**Preserve the baseline configuration while keeping structure, embodiment, experience, and current Reality distinct.**

### 中文固定正文

PHI OS 使用 PHI 构型时，会先保留确定的结构结果，再根据不同证据层逐步展开。核心问题、能力区域、驱动优先级、运动、构型与激活属于方法本身的结构层；它们不会因为后续解释而被重新计算。

当系统进一步读取载体中的构型、经验中的表达或当前现实时，必须加入独立证据。一个出生构型不能自动说明客户现在的身体状态、经验方式或现实优先级。只有当当前环境、资源、选择、压力或客户确认的现实资料存在时，系统才可以形成条件式比较。

因此，PHI 构型在 PHI OS 中不是一张“你是什么”的标签卡，而是一条从基线结构进入现实验证的读取路径。

### Fixed English Copy

PHI OS uses PHI Configuration by preserving the determined structural result first and expanding it only through additional evidence layers. Core Question, Capability Region, Driver Priority, Motion, Configuration, and Activation belong to the method's structural layer and are not recalculated by later interpretation.

When the system moves into Embodied Configuration, Experience Expression, or Current Reality, independent evidence is required. A birth-based configuration cannot automatically establish a customer's present bodily state, lived experience, or current priority. Conditional comparison becomes possible only when evidence about environment, resources, choices, pressure, or confirmed circumstances is available.

PHI Configuration therefore functions not as a label describing “what you are,” but as a reading path from baseline structure toward observation and Reality comparison.
