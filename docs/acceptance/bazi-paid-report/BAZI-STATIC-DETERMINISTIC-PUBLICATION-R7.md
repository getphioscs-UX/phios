# BaZi Static + Deterministic Publication Authority R7

## Status

Canonical customer publication authority: **STATIC_EDITORIAL + DETERMINISTIC_PERSONALIZED**.

Provider-generated T3 prose is not required for customer publication and is not allowed to replace static section openers, static Key Insights or the deterministic personalized analysis structure.

## Publication rhythm

Each section follows the existing report runtime and page-family system. No parallel report runtime is introduced.

- Section opener: fixed bilingual editorial copy.
- Method/chart pages: deterministic personalized data and visuals from the admitted BaZi engine.
- Personalized explanation pages: deterministic composition from licensed BaZi explanatory claims.
- Key Insights: fixed bilingual editorial summary aligned to the chapter architecture.
- Timing pages: deterministic resolved temporal layers when available.
- T3: QA/editorial experiment only, explicit opt-in required.

## R7 density rule

Long-form narrative pages are used only where evidence density can reliably support the narrative-family minimum content budget.

Short, high-density facets such as conditions, boundaries, friction, retention and direction use the existing structured-analysis family instead of padding the report with filler.

No page may be lengthened solely to satisfy a page-family minimum.

## Authority boundaries

Static editorial copy may explain chapter purpose and reading logic but must not create person-specific method facts.

Deterministic personalized copy may only reorganize admitted facts and licensed interpretation claims. It must preserve open judgments, scope boundaries and temporal distinctions.

Calculated facts, method interpretation, editorial explanation and lived-reality evidence remain separate evidence levels.

Financial sections do not create financial advice. Health sections do not create diagnosis. Relationship sections do not infer another person's hidden motives or guarantee outcomes.

## T3 retirement from publication gate

Historical T3 snapshots, rejection records and QA artifacts remain immutable evidence of the previous approach.

They no longer gate production publication.

Provider generation requires explicit QA-only opt-in through `BAZI_T3_EDITORIAL_EXPERIMENT=enabled`.

A configured API key is capability only and does not activate or authorize T3 publication.
