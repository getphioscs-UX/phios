## MCD-0

MCD is a delivery layer. It cannot define Method truth, mutate Method Registry authority, grant Production authority, create Interpretation, or create Professional Judgment. MPA remains the only Production eligibility/dispatch authority.

## MCD-1

- **AST**: a versioned initial Production policy successor authorizes only deterministic core-10 planetary calculation/projection. Houses, angles, aspects, nodes, interpretation, and professional judgment remain deferred. This avoids inventing astrology defaults.
- **BZR**: the historical conditional-license gap is closed for a bounded deterministic calculation/projection scope using the already-recorded IANA TZDB 2026c public-domain authority, Astronomy Engine MIT authority, and PHI OS-owned Bazi policy/rules.
- **NUM**: the PHI OS-owned deterministic numeric rule scope is explicitly accepted for commercial calculation/projection and MPA grants Production authority for that bounded scope.
- **HDR**: fully registered for historical/validation continuity but remains `BLOCKED`, `productionEligible=false`, `professionalEligible=false`, `executionMode=validation_only`, and `dispatchAllowed=false`. No public customer result or Production result tab is created.

## Important distinction

At MCD-1, MPA `dispatchAllowed=true` for AST/BZR/NUM means the authority gate is resolved. Physical Production invocation is still inactive because the canonical Adapter Registry belongs to **MCD-2**. The current `/api/method-execute` adapter placeholder is preserved.

This preserves: `Implemented != Production`, `Registered != Dispatch Allowed`, and `Frontend Visibility != Execution Authority`.
