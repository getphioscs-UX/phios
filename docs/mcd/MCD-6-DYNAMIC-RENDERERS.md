# MCD-6 | Dynamic Renderers

Baseline: `2bd7fd80da907a53f5f4a0f5c0e2db0a87100a4e` (`mcd-5`). Source attachment baseline: `14ec8f4907e13acb0b806c1920f51aab43132835`.

MCD-6 is a renderer-only successor to the frozen MCD-5 `CanonicalMethodProjection` contract. The execution order remains `MCD-4 -> MCD-5 -> MCD-6 -> MCD-7 -> MCD-8`.

## Authority

Renderer may perform presentation geometry, SVG layout, collision handling, responsive layout and accessible alternatives. It may not calculate Method values, normalize raw runtime output, interpret, decide Meaning, create Reality Truth, create Professional Judgment, fill Unknown, call AI, or override MPA.

Production rendering for Astrology, Bazi and Numerology requires all of: an MCD-5 canonical projection, `method.status=PRODUCTION_BOUND_SCOPE`, `execution.mpaDecision.authorityOwner=MPA`, `dispatchAllowed=true`, `projection.clientRenderable=true`, and `projection.productionResult=true`.

## AST

The wheel always uses presentation-only zodiac geometry. Planet positions, degrees and retrograde flags are read from canonical calculation facts. Houses, cusps and aspects are rendered only if corresponding canonical structure facts are already present. Their absence is shown as absence/Unknown; MCD-6 never calculates them. This is especially important while upstream AST Production authority remains scope-limited.

## BZR

Four Pillars, hidden stems, element distribution and cycles are read from canonical structures/cycles. If canonical Unknown declares missing birth time, no hour pillar is rendered even if a malformed upstream payload attempts to supply one. Ten-God content requires both a canonical Ten-God structure and explicit `RULE_SOURCE` evidence containing Ten-God authority.

## NUM

Core numbers, reduction paths, cycles, timeline, evidence, missing values and calculation expansion are rendered from MCD-5 canonical calculation facts. Renderer identity-binds `MFIG-035` through `MFIG-040`; semantic names remain unresolved until an authoritative MFIG registry exists.

## Cross-method composition

MCD-6 does not compare AST/BZR/NUM values. Its cross-method renderer accepts only `CanonicalCrossMethodCompositionProjection`, whose `CONVERGENCE`, `DIVERGENCE` and `UNKNOWN` signals have already been classified upstream. This makes renderer-side Meaning creation structurally impossible. It identity-binds `MFIG-041` through `MFIG-050` without inventing semantic titles.

## Evidence, uncertainty and lineage

All method renderers expose Result, Evidence, Calculation, Projection, Uncertainty and Source panels. Status glyphs are a presentation of existing canonical states, not newly inferred Method facts. Unknown remains visible.

## HDR

The controlled public label is `Personal Runtime Projection` / `个人运行投射`. The renderer is `VALIDATION_ONLY`; Production dispatch, real customer output and professional output remain blocked. The existing MCD-5 validation-only renderer fixture is used for accessibility/responsive contract validation and cannot be promoted by renderer existence.

## Surface boundary

MCD-6 does not modify `personal-runtime.html`, `my-reality.html`, or any client result tab. MCD-7 owns Personal Runtime result-surface binding.
