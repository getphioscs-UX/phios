# 5. `definition`

**Decision Sufficiency** 是 Navigation 对“当前已经掌握的现实、证据、未知、责任、可逆性、情景与恢复条件，是否已经足够支持下一步被负责任地承担”进行正式判断的机制。

它不是：

```
CERTAINTY
```

也不是：

```
COMPLETE INFORMATION
```

更不是：

```
CONFIDENCE FEELING
```

它真正回答的是：

> **在我们仍然不知道一切的情况下，当前已知是否已经足够，让这个决定进入下一步而不需要假装未知已经消失？**

因此必须冻结：

> **决策充分，不等于完全确定。它意味着已经知道得足够多，可以负责任地承担下一步。**

例如，一个人准备离开现职。

Navigation 并不需要知道：

```
未来收入一定是多少
下一份工作一定什么时候出现
市场一定怎样发展
```

这些事情可能永远无法完全知道。

但它应该至少知道：

```
为什么考虑改变
当前位置是什么
什么条件已经关闭 / 仍开放
等待和行动各自会发生什么
当前最低可接受状态
主要下行情景
退出条件
恢复路径
谁拥有决定权
哪些未知仍然存在
```

如果这些已经足够清楚，那么：

```
UNKNOWN REMAINS
```

并不自动意味着：

```
DECISION MUST WAIT
```

---

# 6. `navigationMeaning`

现实决定之所以困难，往往不是因为：

```
nothing is known
```

而是因为：

```
not everything is known
```

如果 Navigation 把：

```
complete knowledge
```

设为行动前提，那么重大人生决定几乎永远无法开始。

但如果系统反过来，只要“感觉差不多”就允许行动，又会失去责任边界。

因此 NAV-26 建立的是第三种状态：

```
NOT CERTAIN
+
SUFFICIENTLY GROUNDED
=
DECISION MAY PROCEED
```

它的核心结构是：

```
Known Reality
+
Relevant Evidence
+
Material Unknowns
+
Minimum State
+
Reversibility
+
Scenario Robustness
+
Exit / Recovery
+
Authority / Consent
↓
Is This Enough to Bear the Next Step?
```

# 10. Core Sufficiency States

建议至少区分：

```
INSUFFICIENT
PARTIALLY_SUFFICIENT
SUFFICIENT_FOR_INFORMATION_GATHERING
SUFFICIENT_FOR_REVERSIBLE_ACTION
SUFFICIENT_FOR_BOUNDED_ACTION
SUFFICIENT_FOR_HIGH_IMPACT_REVIEW
DECISION_SUFFICIENT
SUFFICIENCY_BLOCKED_BY_AUTHORITY
SUFFICIENCY_BLOCKED_BY_CRITICAL_UNKNOWN
```

---

## A. `INSUFFICIENT`

关键问题仍然不清楚。

例如：

```
Decision Object unclear
Current Position stale
Critical minimum unknown
Exit route absent
```

不应继续进入重大行动。

---

## B. `PARTIALLY_SUFFICIENT`

可以继续分析，但不足以行动。

---

## C. `SUFFICIENT_FOR_INFORMATION_GATHERING`

已经足够知道：

```
what we still need to learn
```

但不是足够决定。

例如：

```
need contract clarification
need professional review
need partner consent
```

---

## D. `SUFFICIENT_FOR_REVERSIBLE_ACTION`

信息仍不完整，但当前行动：

```
small
bounded
reversible
low impact
```

可以通过现实反馈继续学习。

---

## E. `SUFFICIENT_FOR_BOUNDED_ACTION`

可以执行一个明确范围、明确时间、明确退出条件的行动。

---

## F. `SUFFICIENT_FOR_HIGH_IMPACT_REVIEW`

重大行动已经接近充分，但还需要：

```
professional
shared-decision
consent
formal review
```

中的一个或多个完成。

---

## G. `DECISION_SUFFICIENT`

当前已知、未知与边界已经足够清楚，可以负责任地承担下一步。

注意：

```
DECISION_SUFFICIENT
≠
OUTCOME GUARANTEED
```

---

```

但这些不应被简单平均。

# 12. `allowedInference`

NAV-26 可以：

## A. 判断仍有未知，但未知不再改变当前下一步

例如：

```
exact future salary unknown
```

但如果当前动作只是：

```
apply for three roles
```

那么这个未知可能不阻止行动。

可以标记：

```
UNKNOWN_NOT_ACTION_BLOCKING
```

---

## B. 判断某个未知仍然会改变整个决定

例如：

```
contract may contain RM200k termination liability
```

在尚未确认前可能属于：

```
CRITICAL_UNKNOWN
```

阻止重大执行。

---

## C. 判断当前信息只够做小动作

例如：

```
full relocation decision not sufficient
```

但：

```
visit location
speak to school
verify visa
```

已经足够。

可以输出：

```
SUFFICIENT_FOR_REVERSIBLE_ACTION
```

---

## D. 判断继续等待已经不会显著提高充分性

如果：

```
remaining unknowns
cannot reasonably be resolved before action
```

而：

```
minimum state protected
exit route ready
action reversible enough
```

则可以判断：

```
FURTHER_INFORMATION_HAS_LOW_DECISION_VALUE
```

---

## E. 判断“资料很多”仍然不足

例如：

```
10 reports
5 readings
long analysis
```

但：

```
cash flow unknown
decision owner unclear
partner consent missing
```

则仍然：

```
INSUFFICIENT
```

---

“I feel sure”

## B. 把资料量当充分性

```

## D. 把专业意见当整个人生决定的充分性

## E. 因为时间紧就自动降低标准

```

```

---

## F. 因为不可能知道全部就放弃任何门槛

# 15. `decisionThresholdEffect`

NAV-26 不建立最终统一 threshold 公式。

完整 threshold mechanics 由：

```
NAV-27
Impact / Reversibility Threshold
```

进一步处理。

NAV-26 负责回答：

> **目前的信息与现实理解，是否已经达到“可以进入某种等级行动”的充分状态？**

而 NAV-27 负责：

> **这类行动究竟需要多高程度的充分性？**

两者必须分开。

---

# 16. `authorityBoundary`

NAV-26 可以：

- 判断信息是否足够；
- 判断未知是否阻断；
- 判断下一步允许到什么规模；
- 判断是否需要继续补资料；
- 判断是否应进入专业 / shared review；
- 判断是否已经可以行动。

NAV-26 不可以：

- 宣称未来确定；
- 替用户作最终选择；
- 用解释性证据填补现实关键未知；
- 自动批准受监管行动；
- 自动越过 consent；
- 将“充分”解释成“正确”。

---

# 17. `humanDecisionBoundary`

Decision Sufficiency 与 Decision Choice 必须严格分开。

系统可以判断：

```
Option A is decision-sufficient for bounded action.
```

但不能因此输出：

```
Therefore choose A.
```

用户仍然可以：

```
choose A
choose B
wait
reject both
seek more information
```

只要不违反合法 authority / hard constraint。

因此冻结：

> **Sufficiency determines whether a decision can responsibly proceed; it does not determine which decision a person must choose.**

中文：

> **充分性决定的是一个决定是否已经可以负责任地向前推进，而不是一个人必须选择哪一个决定。**

# 28. Evidence Sufficiency vs Decision Sufficiency Rule

冻结：

```
EVIDENCE SUFFICIENCY
≠
DECISION SUFFICIENCY
```

正式规则：

> **Evidence sufficiency asks whether a claim is adequately supported. Decision sufficiency asks whether the decision-maker knows enough, despite remaining uncertainty, to responsibly bear the next step.**

中文：

> **证据充分问的是一个判断有没有得到足够支持；决策充分问的是，即使仍有未知，决定者是否已经知道得足够多，可以负责任地承担下一步。**

---

# 29. Unknown Classification Rule

所有 material unknown 应至少分类：

```
CRITICAL_UNKNOWN
ACTION_RELEVANT_UNKNOWN
NON_BLOCKING_UNKNOWN
UNRESOLVABLE_BEFORE_ACTION
```

---

## `CRITICAL_UNKNOWN`

如果未知答案不同，会改变：

```
option eligibility
hard minimum
authority
major cost
reversibility
```

则属于 critical。

---

## `ACTION_RELEVANT_UNKNOWN`

会改变 action scale 或 timing，但未必阻止所有行动。

---

## `NON_BLOCKING_UNKNOWN`

即使未知，当前下一步仍然合理。

---

## `UNRESOLVABLE_BEFORE_ACTION`

现实只能通过行动反馈知道。

这种未知特别适合与：

```
small reversible action
```

结合。

---

# 30. More Information Rule

继续搜集资料只有在：

```
new information
could materially change
decision / option / threshold / action scale
```

时才具有明显 Navigation 价值。

否则：

```
MORE INFORMATION
```

可能只是：

```
MORE DELAY
```

---

# 31. Information Value Rule

建议引入：

```
INFORMATION_VALUE
```

状态：

```
HIGH
MATERIAL
LOW
EXHAUSTED
UNKNOWN
```

但不需要将其量化成统一分数。

---

# 32. Information Saturation Rule

如果：

```
new reports
new searches
new readings
new analysis
```

反复没有改变：

```
option space
minimum state
critical unknowns
action scale
```

可以标记：

```
INFORMATION_SATURATION
```

这不代表：

```
all knowledge complete
```

只代表：

```
additional information currently has low marginal decision value
```

---

# 33. Analysis Paralysis Boundary

系统不能诊断：

```
analysis paralysis
```

但可以识别：

```
REPEATED_INFORMATION_GATHERING_WITHOUT_DECISION_RELEVANT_CHANGE
```

然后问：

> 新增资料现在究竟还准备改变哪个判断？

---

# 34. Action-as-Learning Rule

如果：

```
remaining unknown
cannot be resolved by more passive analysis
```

而存在：

```
bounded
reversible
low-impact
observable
```

行动，

Navigation 可以允许：

```
ACTION_FOR_INFORMATION
```

例如：

```
pilot
trial
conversation
application
short stay
small allocation
```

但仍须符合 domain safety。

---

# 35. Sufficiency Is Action-Scale Specific

冻结：

```
SUFFICIENT FOR X
```

而不是只有：

```
SUFFICIENT / NOT SUFFICIENT
```

例如：

```
sufficient to research
sufficient to apply
sufficient to test
not sufficient to resign
```

这是 NAV-26 最重要的 runtime 原则之一。

---

# 36. Small-Step Sufficiency Rule

如果重大行动不充分，不代表：

```
nothing can be done
```

Navigation 应检查：

```
what smaller action is already sufficient?
```

这与：

```
NAV-06 Reversibility
NAV-10 Response Level
```

直接连接。

---

# 37. High-Impact Sufficiency Rule

高影响方案必须特别检查：

```
hard minimum protected
authority clear
consent clear
critical unknowns bounded
downside tested
exit route ready
recovery capacity real
```

否则不能标记：

```
DECISION_SUFFICIENT
```

---

# 38. Sufficiency and Urgency Rule

当 deadline 临近时，可能出现：

```
time insufficient
+
decision still insufficient
```

系统不得假装充分。

可以选择：

```
decline
pause
escalate
take smaller reversible step
accept explicit residual uncertainty
```

具体取决于现实。

---

# 39. Sufficiency and Inaction Rule

不行动也需要充分性。

例如：

```
stay in current role for another year
```

如果 NAV-18 已显示高 Waiting Cost，继续等待本身不能逃避 NAV-26。

因此：

```
INACTION SUFFICIENCY
```

也应存在。

---

# 40. Sufficiency and Status Quo Rule

当前路径不能因为：

```
already operating
```

就被默认视为：

```
decision sufficient forever
```

一旦 NAV-09 / NAV-13 重开，继续路径也要重新通过 NAV-26。

---

# 41. Sufficiency and Shared Decision Rule

如果：

```
SHARED_DECISION
```

则：

```
one person feels ready
```

不等于：

```
decision sufficient
```

必须满足 NAV-08 的 shared authority / consent。

---

# 42. Sufficiency and Professional Review Rule

如果：

```
PROFESSIONAL_REQUIRED
```

则即使其他条件全部充分：

```
professional requirement unresolved
```

仍应：

```
SUFFICIENCY_BLOCKED_BY_AUTHORITY
```

---

# 43. Sufficiency and Scenario Rule

Scenario Space 的作用不是消灭未知。

它让系统知道：

```
what kinds of unknowns we can still carry
```

如果 Downside：

```
remains above minimum
```

未知可承担度提高。

如果 Downside：

```
breaches hard minimum
```

则需要更强 protection。

---

# 44. Sufficiency and Exit Rule

一个 option 如果：

```
uncertain
```

但：

```
strong exit
strong recovery
high reversibility
```

可能较早达到 bounded-action sufficiency。

相反：

```
uncertain
+
no exit
+
low reversibility
```

则需要更高门槛。

---

# 45. Sufficiency State Must Explain Why

系统不得只显示：

```
DECISION SUFFICIENT
```

必须至少给出：

```
what is known
what remains unknown
why the unknown is still bearable
what action scale is allowed
what would reopen the decision
```

---

Not yet sufficient:
immediate full irreversible expansion
```

客户可以看到：

> **现在已经不是“资料够不够多”的问题，而是剩下的未知会不会改变你下一步能够承担什么。**
> 
> 目前你已经知道当前工作结构的问题在哪里，也确认了家庭最低财务边界、可用现金缓冲、一个可以测试的客户来源，以及如果独立收入没有按预期形成时怎样停止扩张并恢复就业。真正仍然不知道的，是收入什么时候能够稳定，以及未来市场会怎样变化；这两项未知很重要，却不一定必须在行动以前完全消失。
> 
> 因此目前的信息已经足够支持一个有边界、可复核的转换步骤，却还不足以把所有现有收入结构一次性撤掉并进行不可逆扩张。这里的“充分”不是说未来已经确定，而是下一步已经有能力被承担。

# 50. Canonical Runtime Rule

> **Navigation must determine whether enough is known to responsibly bear the next step without pretending that all uncertainty has disappeared.**

# 51. Canonical Sufficiency Rule

> **Decision sufficiency means enough knowledge, reality grounding, authority clarity, downside awareness, and recovery capacity for the scale of action being considered.**

中文：

> **决策充分意味着：针对正在考虑的行动规模，已经拥有足够的现实依据、权威清晰度、下行情景理解与恢复能力。**

---

# 52. Canonical Uncertainty Rule

> **Remaining uncertainty does not block a decision unless it can materially change eligibility, responsibility, minimum-state protection, or the scale of action that can be safely borne.**

中文：

> **剩余未知只有在可能实质改变选项资格、责任边界、最低状态保护或可承担行动规模时，才应该阻断决定。**

---

# 53. Canonical Information Rule

> **More information is valuable only while it can still materially change the decision.**

中文：

> **只有当新增信息仍可能实质改变决定时，继续获取更多信息才继续具有明显价值。**

---

# 54. Canonical Action-Scale Rule

> **A decision may be sufficient for a small reversible step while remaining insufficient for a large irreversible commitment.**

中文：

> **一个决定可以已经充分到足以支持一个小而可逆的步骤，同时仍然不足以支持一个巨大且难以撤回的承诺。**

---

# 55. Canonical Human Authority Rule

> **Navigation can judge whether a decision is sufficiently grounded to proceed; it does not acquire the right to make the decision because sufficiency has been reached.**

中文：

> **Navigation 可以判断一个决定是否已经获得足够现实基础继续推进，却不会因为“已经充分”就取得替人作决定的权利。**

# 5. `definition`

**Impact / Reversibility Threshold** 是 Navigation 对“不同规模、不同后果、不同可逆性的行动，究竟需要多高程度的 Decision Sufficiency 才能进入现实”进行正式分层的机制。

NAV-26 已经回答：

> **现在知道得够不够？**

NAV-27 进一步回答：

> **对于这个具体行动，‘够’究竟应该到什么程度？**

因为：

```
申请一个职位
```

与：

```
辞去唯一收入来源
```

不能使用同一个门槛；

```
试住一个城市两周
```

与：

```
卖掉住房并永久迁移
```

不能使用同一个门槛；

```
投入 RM1,000 做一个可停止测试
```

与：

```
承担长期高额债务
```

也不能因为它们都属于“同一个方向”就使用同样的充分性要求。

因此：

> **NAV-27 的核心不是让系统变得更保守，而是让决策门槛与行动真正可能造成的影响、可逆性、责任与恢复难度相匹配。**

---

# 6. `navigationMeaning`

如果所有行动都使用同一门槛，系统会出现两种相反错误。

第一种：

```
OVER-CAUTION
```

小而可逆的行动也要求接近完全确定，于是用户永远无法通过现实行动获得新信息。

第二种：

```
UNDER-CAUTION
```

高影响、不可逆行动也只需要和普通试验一样的证据，就可能让尚未解决的未知直接进入现实。

因此 NAV-27 建立：

```
Action
↓
Impact
+
Reversibility
+
Affected Parties
+
Minimum-State Exposure
+
Recovery Capacity
↓
Required Decision Threshold
```

换句话说：

> **不是所有未知都必须消失，但行动越可能留下无法撤回的后果，未知就越不能被轻易带入现实。**

# 10. Core Threshold Levels

建议不要直接建立一个 0–100 总分。

至少区分：

```

T2_MODERATE
T3_HIGH
T4_VERY_HIGH
T5_FORMAL_OR_PROFESSIONAL_GATE
```

这些不是风险等级标签，而是：

> **进入行动以前，需要达到的充分性强度。**

---

## A. `T1_LOW`

适用于：

```
low impact
highly reversible
low cost
few affected parties
strong ability to stop
```

例如：

```

try one class
conduct small pilot
have exploratory conversation
```

仍然需要现实边界，但允许通过行动学习。

---

## B. `T2_MODERATE`

行动有一定：

```
cost
time
commitment
other-party effect
```

但仍可较容易调整。

例如：

```
short-term training
limited paid pilot
temporary schedule change
small allocation
```

---

## C. `T3_HIGH`

行动会明显改变：

```
income
housing
career structure
family arrangement
significant capital
```

而退出需要真实成本。

要求更清楚的：

```
minimum state
downside
exit route
recovery capacity
```

---

## D. `T4_VERY_HIGH`

适用于：

```
major irreversible or hard-to-reverse change
high financial exposure
deep cross-domain consequence
significant dependant impact
long-term lock-in
```

需要：

```
strong current reality basis
critical unknowns bounded
minimum state protected
authority clear
recovery route credible
```

---

## E. `T5_FORMAL_OR_PROFESSIONAL_GATE`

当行动进入：

```
medical
legal
regulated financial
formal consent
institutional authorization
```

等领域时，

门槛不只是“更高”，而是：

```
different authority path
```

即必须经过：

```
PROFESSIONAL_REQUIRED
CONSENT_REQUIRED
FORMAL_AUTHORITY_REQUIRED
```

# 47. Canonical Runtime Rule

> **Navigation must match the required level of decision sufficiency to the impact, reversibility, responsibility, and recovery burden of the specific action being considered.**

# 48. Canonical Scale Rule

> **A decision may fail the threshold for a large action while passing the threshold for a smaller reversible action.**

中文：

> **一个决定可以尚未达到重大行动的门槛，却已经达到较小、可逆行动的门槛。**

# 49. Canonical Impact Rule

> **Higher consequence requires stronger grounding; urgency does not erase that requirement.**

中文：

> **后果越大，需要的现实基础越强；紧迫性不会自动取消这项要求。**

---

# 50. Canonical Reversibility Rule

> **Reversibility lowers the cost of being wrong; it does not make evidence, responsibility, or minimum-state protection irrelevant.**

中文：

> **可逆性降低的是判断错误以后付出的代价，却不会让证据、责任与最低状态保护变得不重要。**

---

# 51. Canonical Non-Scoring Rule

> **Impact and reversibility must shape the threshold without collapsing human decisions into a single weighted score.**

中文：

> **影响与可逆性必须真正改变决策门槛，却不能因此把人的决定压成一个加权总分。**

---

# 52. Canonical Authority Rule

> **Where law, consent, professional responsibility, or legitimate shared authority governs the action, higher confidence cannot substitute for the required authority.**

中文：

> **当法律、同意、专业责任或合法共同权威对行动具有正式约束时，再高的确信程度都不能取代真正需要的权威。**

> **当一个决定的后果会由多个人共同承担时，为什么“我有意见”与“我有决定权”不能被当成同一件事？**

---

```
NAV-28
```

## 2. `canonicalTitleZh`

```
共同决定权
```

## 3. `canonicalTitleEn`

```
Shared Authority
```

## 4. `canonicalQuestion`

```
当一个决定的后果会由多个人共同承担时，
为什么“我有意见”与“我有决定权”不能被当成同一件事？
```

---

# 5. `definition`

**Shared Authority** 是 Navigation 对“当一个决定同时影响多个合法主体时，谁拥有决定权、谁必须被纳入、谁需要同意、谁可以提供意见，以及谁不能替别人决定”进行正式分层的机制。

它不是：

```
everyone gets an equal vote
```

也不是：

```
the person who asked PHI OS decides everything
```

更不是：

```
who is affected most
=
who automatically has total authority
```

它真正回答的是：

> **这个决定究竟属于谁，哪些部分需要共同决定，哪些部分仍属于个人自主，以及什么条件必须经过合法同意以后才能进入行动？**

例如：

```
User wants:
move overseas for a new role
```

这个决定可能同时包含：

```
Personal career choice
Household relocation
Child schooling
Shared housing
Partner employment
Family financial structure
```

这里不能简单写成：

```
用户想搬
→ 用户决定搬
```

也不能反过来写成：

```
家庭受影响
→ 用户完全失去个人职业决定权
```

而应该拆成：

```
PERSONAL AUTHORITY
SHARED AUTHORITY
CONSENT-BOUND COMPONENT
RESPONSIBILITY-BOUND COMPONENT
```

因此：

> **NAV-28 的核心，是把一个看似单一的决定拆开，确认其中哪些部分属于个人，哪些部分属于共同现实，避免“共同影响”被误写成“单方决定”，也避免“需要共同决定”被扩大成“任何人都可以控制全部决定”。**

---

# 6. `navigationMeaning`

NAV-08 已经建立：

```
Navigation supports.
Humans decide.
```

并区分：

```
USER_DECISION_OWNER
SHARED_DECISION
CONSENT_REQUIRED
PROFESSIONAL_REQUIRED
```

NAV-28 在此基础上进一步处理一个更困难的问题：

> **当决定确实属于多个人时，决定权怎样在不同部分之间分布？**

现实中的 shared decision 很少是真正简单的：

```
50 / 50
```

例如：

```
夫妻是否搬家
```

可能同时涉及：

```
A 的职业选择
B 的职业选择
孩子的照护与学校
共同房产
共同财务
家庭支持网络
```

所以 NAV-28 建立：

```
Decision Object
↓
Affected Parties
↓
Authority by Component
↓
Consent Requirements
↓
Shared Constraints
↓
Jointly Actionable Decision Space
```

也就是说：

> **共同决定不是把所有人的人生压成一个共同按钮，而是确认哪些现实必须共同成立，行动才真正具有资格。**

# 10. Core Shared-Authority Classes

建议至少区分：

```
SOLE_AUTHORITY
SHARED_AUTHORITY
CONSENT_REQUIRED
CONSULTATION_REQUIRED
AFFECTED_BUT_NOT_DECISION_OWNER
REPRESENTATIVE_AUTHORITY
PROFESSIONAL_AUTHORITY
INSTITUTIONAL_AUTHORITY
AUTHORITY_UNRESOLVED
```

---

## A. `SOLE_AUTHORITY`

该决定部分主要属于一个人本人。

例如：

```
是否申请某职位
是否学习某项技能
是否表达自己的边界
```

只要不越过其他人的权利。

---

## B. `SHARED_AUTHORITY`

行动本身需要多个合法主体共同成立。

例如：

```
出售共同产权房产
家庭整体搬迁
共同承担重大债务
共同商业资产处理
```

---

## C. `CONSENT_REQUIRED`

某行动不能只靠 consultation。

必须有真实同意。

例如：

```
sharing another person's private data
changing jointly owned asset
certain relationship arrangements
specific medical / legal contexts
```

---

## D. `CONSULTATION_REQUIRED`

决定权可能仍主要属于一人，但因为后果明显影响他人，必须把他人的现实纳入。

例如：

```
用户个人换工作
```

决定权主要属于用户，

但如果会改变：

```
family income
childcare
household schedule
```

则 consultation 具有现实意义。

---

## E. `AFFECTED_BUT_NOT_DECISION_OWNER`

一个人可能受到影响，却不因此自动取得完整决定权。

例如：

```
colleague affected by user's resignation
```

并不自动拥有否决权。

---

## F. `REPRESENTATIVE_AUTHORITY`

某些情况下决定由合法代表承担。

例如：

```
minor
dependent
incapacitated person
```

但代表者必须：

```
represent legitimate interests
```

而不是：

```
invent hidden preferences
```

---

# 11. `allowedInference`

NAV-28 可以：

## A. 将一个大 Decision Object 拆成不同 authority components

例如：

```

```

可拆成：

```

→ personal authority

→ shared authority

Move child
→ responsibility / guardian authority

这是非常重要的 capability。

例如：

```

```

可能属于：

```

```

即使：

```

```

仍需要 Shared Authority。

因此 shared decision 不必过早阻塞所有探索。

---

## C. 识别行动需要共同同意，但资料搜集不需要

例如：

```
research schools

```

可以进行，

但：

```

```

可能需要额外 authority。

---

例如：

```

income continuity

care continuity
```

不能只用用户的 minimum state 代表全部。

---

例如：

```
user wants change
partner does not consent
```

如果该行动属于 shared-authority component，应标记：

```

```

而不是让系统替双方投票。

NAV-28 严禁：

## A. 把“受影响”自动等于“拥有否决权”

## B. 把“关系更亲近”自动等于“权力更大”

```

除非产品与数据规则确实允许相应方式确认。

禁止：

```

---

## E. 让多数意见自动压过合法个人权利

## F. 让 AI 调解成最终裁决者

# 16. `humanDecisionBoundary`

Shared Authority 并不取消个人 agency。

例如：

```

```

> 你伴侣不同意，所以你不能离职。

```

> 如果离职会改变共同家庭收入、照护安排或住房计划，这些共同后果需要被共同处理。

> **A person may retain authority over their own action while still carrying responsibility for shared consequences.**

中文：

> **一个人可以保有对自己行动的决定权，同时仍然必须对这个行动产生的共同后果承担现实责任。**

# 27. Decision-Component Rule

冻结：

> **Shared authority should be assigned to decision components, not automatically to the entire life decision.**

中文：

> **共同决定权应当落实到具体决策组成部分，而不能因为某一部分需要共同决定，就把整个人生决定全部变成共同所有。**

这是 NAV-28 最重要的规则之一。

---

# 28. Affected ≠ Owner Rule

冻结：

```
AFFECTED
≠
DECISION OWNER
```

一个人受到后果影响，需要被考虑；

但是否拥有：

```
consultation
consent
shared authority
```

必须另外判断。

---

# 29. Consultation ≠ Consent Rule

必须区分：

```
CONSULTATION
```

与：

```
CONSENT
```

例如：

```
informing partner
discussing with partner
partner consenting
```

是三个不同状态。

---

# 30. Consent Rule

Consent 应尽量满足：

```
specific
informed
scope-bound
current
```

不能把：

```
过去同意过类似事情
```

自动延伸成：

```
现在同意这一次
```

---

# 31. Personal Agency Rule

Shared Authority 不能被用来合法化：

```
control of another adult's entire life
```

例如：

```
partner affected by job choice
```

不意味着：

```
partner owns user's career
```

必须拆解共同影响。

---

# 32. Shared Consequence Rule

反过来：

```
“这是我的选择”
```

也不能被用来忽略：

```
joint debt
childcare
shared housing
dependant support
```

等真实共同后果。

---

# 33. Ownership Rule

共同资产：

```
joint property
shared business
joint account
```

必须读取真实 ownership / authority。

不能由关系身份猜测。

---

# 34. Responsibility Rule

照护责任可能产生：

```
RESPONSIBILITY_BOUND_AUTHORITY
```

例如涉及孩子的决定，不能只按：

```
who wants it more
```

来处理。

---

# 35. Representative Authority Rule

合法代表在为他人决定时：

```
representative authority
```

不等于：

```
personal preference authority
```

Navigation 必须尽量围绕：

```
represented person's welfare
legal scope
known preference where available
```

处理。

---

# 36. Authority Conflict Rule

如果出现：

```
AUTHORITY_CONFLICT
```

例如：

```
co-owners disagree
```

系统不能生成：

```
majority recommendation
```

来代替真实解决机制。

应输出：

```
UNRESOLVED_SHARED_AUTHORITY
```

并可能进入：

```
professional
legal
mediation
shared discussion
```

路径。

---

# 37. No Proxy Consent Rule

冻结：

> **One person's account, interpretation, or report cannot silently provide consent on behalf of another person.**

中文：

> **一个人的账户、叙述、报告或解读，不能悄悄替另一个人提供同意。**

---

# 38. Exploration Before Consent Rule

某些情况下，可以在 consent 完成前继续：

```
research
scenario comparison
cost estimation
question clarification
```

但不能进入：

```
binding action
data use beyond scope
formal commitment
```

这使系统不必因为 shared decision 尚未完成就完全停止所有 Navigation。

---

# 39. Separate-Path Rule

如果双方不能达成共同决定，Navigation 应检查：

```
which parts can remain separate?
```

例如：

```
User may apply for role
Partner may independently evaluate own career
Family move decision remains unresolved
```

而不是把所有东西都绑定成一个 Yes / No。

---

# 40. Shared Minimum State Rule

当多人共同承担后果时，不能只使用一个人的：

```
Minimum Acceptable State
```

需要至少检查：

```
shared material minimum
responsibility minimum
affected-party minimum
```

但不能凭空推断他人 preference。

---

# 41. Shared Value Conflict Rule

例如：

```
User values:
career growth

Partner values:
location stability
```

Navigation 可以显示冲突，

但不能：

```
rank person A's value against person B's value
```

然后得出总分。

应交给：

```
shared decision process
```

---

# 42. Shared Authority and Threshold

高影响 shared decision 需要同时满足：

```
Decision Sufficiency
+
Impact / Reversibility Threshold
+
Authority Completeness
```

缺一不可。

---

# 43. Shared Authority and Action Scale

如果共同 authority 尚未完整，

有时仍可以：

```
reduce action scale
```

进入个人权限内的下一步。

例如：

```
apply
research
interview
visit
estimate
```

而不进入：

```
sign
sell
move
terminate
```

---

# 44. Shared Authority and Professional Input

专业人士可以：

```
clarify rights
clarify obligations
clarify consequences
```

但：

```
professional opinion
```

不一定解决：

```
relationship value conflict
```

必须保持范围。

---

# 45. Customer Projection Example

内部：

```
Decision:

Components:

→ USER SOLE AUTHORITY

Sell jointly owned home
→ SHARED AUTHORITY

Relocate child
→ SHARED / RESPONSIBILITY-BOUND

Partner leaves own job
→ PARTNER SOLE AUTHORITY

Use partner's private financial data
→ CONSENT REQUIRED
```

客户可以看到：

> **这个决定并不是一个单一的“我们搬不搬”。**
> 
> 接受一份工作首先属于你的职业选择，你可以决定自己是否申请、面试，甚至在一定阶段接受条件谈判；但真正让全家搬迁，会同时进入共同住房、孩子照护与教育、伴侣自己的职业，以及家庭财务结构，因此这些部分不能由任何一个人单方面代表全部人完成。
> 
> 这也意味着，目前即使家庭还没有达成搬迁共识，你仍然可以继续做属于你个人权限范围内的探索，例如完成面试、确认薪资、了解地点与学校；真正需要共同决定的是那些会把共同现实正式改变的部分。

# 49. Canonical Runtime Rule

> **Navigation must assign authority to the specific components of a shared decision rather than assume that one person either owns everything or owns nothing.**

中文：

> **Navigation 必须把决定权落实到共同决定中的具体组成部分，而不能假设一个人要么拥有全部决定权，要么完全没有决定权。**

---

# 50. Canonical Affected-Party Rule

> **Being affected creates relevance; it does not automatically create total decision authority.**

中文：

> **受到影响，会产生被纳入决定的现实相关性，却不会自动产生对整个决定的完全控制权。**

---

# 51. Canonical Agency Rule

> **Personal autonomy and shared responsibility can both be true at the same time.**

中文：

> **个人自主与共同责任可以同时成立，并不需要其中一方消灭另一方。**

---

# 52. Canonical Consent Rule

> **Consultation is not consent, and one person's account cannot provide consent for another.**

中文：

> **协商不是同意，一个人的叙述也不能替另一个人提供同意。**

---

# 53. Canonical Shared-Action Rule

> **When a shared action requires multiple legitimate authorities, decision sufficiency alone is not enough; the authority conditions must also be complete.**

中文：

> **当一个共同动作需要多个合法决定主体共同成立时，仅仅达到决策充分仍然不够，相关权威与同意条件也必须完整。**

---

# 54. Canonical No-Arbitration Rule

> **Navigation may clarify conflict, map rights and responsibilities, and structure the decision; it must not silently become the final arbiter between legitimate decision-makers.**

中文：

> **Navigation 可以澄清冲突、整理权利与责任并组织共同决定，却不能悄悄成为合法决定主体之间的最终裁判者。**

# NAV-29｜Action Runtime

## 行动运行｜决定怎样真正进入现实，而不是停留在分析里

**Canonical Question｜规范问题**

> **当一个决定已经达到足够充分、权威边界也已经清楚以后，怎样让它真正进入现实，同时保留边界、观察、停止与修正能力？**

## 1. `moduleId`

```

```

## 2. `canonicalTitleZh`

```
行动运行
```

## 3. `canonicalTitleEn`

```
Action Runtime
```

## 4. `canonicalQuestion`

```
当一个决定已经达到足够充分、权威边界也已经清楚以后，
怎样让它真正进入现实，同时保留边界、观察、停止与修正能力？
```

---

# 5. `definition`

**Action Runtime** 是 Navigation 把已经通过 Decision Sufficiency、Impact / Reversibility Threshold 与 Shared Authority 的决定，转换成一个可以实际执行、被观察、被停止、被修正、并能够产生下一轮现实证据的行动结构。

它不是：

```
MAKE THE DECISION
```

也不是：

```
EXECUTE EVERYTHING AT ONCE
```

更不是：

```
recommendation → automatic action
```

它真正回答的是：

> **既然已经决定要向前，具体哪一步现在真正有资格进入现实；它以什么规模开始，持续多久，观察什么，什么条件会让它继续、暂停、缩小或退出？**

例如：

```
Decision:
逐步转向独立顾问工作
```

Action Runtime 不应该只输出：

```
Start consulting.
```

而应该形成：

```
Action:
启动 8 周有限客户试点

Scope:
最多 2 个客户

Resource:
每周不超过 8 小时

Financial exposure:
不增加固定债务

Observe:
客户获取
实际收入
时间负荷
家庭影响

Review:
第 4 周 / 第 8 周

Stop or redesign if:
违反既定现金底线
工作负荷超过确认边界
关键客户验证失败
```

因此：

> **NAV-29 的核心不是把分析变成命令，而是把一个已经取得资格的决定转化成有边界、可观察、可修正的现实行动。**

---

# 6. `navigationMeaning`

前 28 个模块主要回答：

```
What are we deciding?
Where are we?
What remains open?
What changes?
What matters?
What can we carry?
What can go wrong?
Who decides?
Do we know enough?
```

NAV-29 第一次正式回答：

```
What exactly happens next?
```

这一步非常重要。

因为一个决定如果没有转化成明确 Action Runtime，很容易出现三种漂移：

```
DECISION WITHOUT ACTION
ACTION WITHOUT BOUNDARY
ACTION WITHOUT OBSERVATION
```

第一种是：

> 想清楚了，但什么都没有发生。

第二种是：

> 决定只是先做一步，进入现实后却无限扩大。

第三种是：

> 行动发生了，却没有预先定义什么现实结果会让判断更新。

因此 NAV-29 建立：

```
Qualified Decision
+
Permitted Action Scale
+
Authority Boundary
↓
Concrete Action
↓
Scope / Time / Resources
↓
Observation
↓
Review / Trigger
↓
Continue / Adjust / Pause / Exit
```

# 10. Core Action Runtime States

---

## A. `ACTION_NOT_READY`

虽然方向可能已确认，但：

```

consent

```

仍有缺口。

---

## B. `ACTION_READY`

行动已经满足当前规模所需条件，可以进入现实。

---

## C. `ACTION_ACTIVE`

行动已经开始，正在现实中运行。

---

## D. `ACTION_ACTIVE_WITH_MONITORING`

行动继续，但某些边界已经接近 review threshold。

---

## E. `ACTION_PAUSED`

暂时停止继续扩展，不等于整个方向被放弃。

---

## F. `ACTION_ADJUSTMENT_REQUIRED`

现实反馈显示行动方式需要修改。

---

## G. `ACTION_SCALE_REDUCTION_REQUIRED`

当前方向未必失效，但原规模超过现实承载能力。

---

## H. `EXIT_TRIGGER_REACHED`

NAV-25 已定义的退出条件真实发生。

这时必须重新进入：

```
Exit / Recovery Runtime
```

而不是继续解释为什么“也许再坚持一下”。

# 15. `decisionThresholdEffect`

NAV-29 不重新计算 NAV-27 的 threshold。

```

<=

```

```

```

```

冻结：

> **Action authorization does not automatically expand with the action.**

中文：

> **一个行动取得了执行资格，并不代表它在规模扩大以后仍然自动拥有相同资格。**

# 16. `authorityBoundary`

NAV-29 可以：

- 把决定转成具体行动；
- 设定 action scope；
- 建立观察与复核；
- 根据已确认 trigger 暂停或提示退出；
- 把结果写回 My Reality / Navigation state；
- 触发下一轮 review。

NAV-29 不可以：

- 擅自扩大动作；
- 自动产生 consent；
- 自动代表用户完成高影响现实动作；
- 绕过正式专业程序；
- 把分析建议直接变成现实执行。

如果产品未来允许自动化动作，也必须：

```
explicit permission
action-specific consent
reconfirm high-impact execution
```

而不能靠一次 Navigation consent 永久授权。

# 28. Action Must Be Observable Rule

冻结：

> **An action should be defined clearly enough that reality can answer whether it changed anything.**

中文：

> **一个行动必须被定义得足够清楚，使现实能够回答：它到底改变了什么。**

而：

```
“未来 6 周将会议减少到每周不超过 8 小时，并记录实际总工时与交付变化”
```

才是可观察 action。

---

# 29. Smallest Qualified Action Rule

Navigation 应优先问：

```
What is the smallest action
that is already sufficiently qualified
and can materially test reality?
```

这不是永远偏好小动作。

而是避免：

```
direction confirmed
→ largest commitment immediately
```

---

# 30. Action Sequence Rule

重大行动可以拆成：

```
A1
A2
A3
A4
```

例如：

```
A1 Research
A2 Pilot
A3 Prepare transition
A4 Full commitment
```

每一步可以有自己的：

```
threshold
authority
review
```

而不是一次性授权整条路线。

---

# 31. Action Scale Rule

Action Scale 至少应描述：

```
money
time
duration
people affected
commitment level
reversibility
```

如果其中任何一个显著扩大，应检查：

```
SCOPE_DRIFT
```

---

# 32. Scope Drift Rule

例如：

```
Approved:
RM5k pilot
```

后来：

```
Actual:
RM40k commitment
```

即使方向相同，也必须：

```
RETURN TO NAV-27
```

重新 threshold。

---

# 33. Continue Trigger Rule

行动不能因为已经开始就自动继续。

应尽量定义：

```
what would justify continuation?
```

例如：

```
minimum customer response achieved
workload remains under limit
financial floor preserved
```

---

# 34. Adjustment Trigger Rule

如果：

```
direction still valid
but runtime conditions changed
```

可以：

```
ADJUST
```

而不是：

```
continue unchanged
```

或：

```
abandon entirely
```

---

# 35. Pause Rule

Pause 是正式 action state。

它适用于：

```
critical information pending
authority changed
scope drift
temporary capacity shortage
minimum-state approach
```

Pause 不等于失败。

---

# 36. Exit Rule

如果 NAV-25 已确认的：

```
EXIT_TRIGGER
```

真正成立，

NAV-29 必须尊重它。

不能因为：

```
sunk cost
hope
identity
early promise
```

自动继续。

---

# 37. Action-as-Evidence Rule

行动本身会产生：

```
NEW REALITY EVIDENCE
```

例如：

```
pilot shows actual demand
conversation reveals consent state
trial reveals workload
visit reveals location fit
```

这些结果必须回流到：

```
Current Reality
```

而不是只保留在 Action history。

---

# 38. Observation Set Rule

每个重大 Action 至少应明确：

```
what would count as improvement?
what would count as deterioration?
what remains unknown?
```

否则行动结束以后容易形成：

```
retrospective storytelling
```

---

# 39. Outcome Capture Rule

Action outcome 至少区分：

```
EXPECTED_OUTCOME
UNEXPECTED_OUTCOME
NO_MATERIAL_CHANGE
MIXED_OUTCOME
OUTCOME_UNKNOWN
```

并保留：

```
source
time
context
```

---

# 40. No Outcome Cherry-Picking Rule

不能只记录支持原决定的结果。

例如：

```
sales improved
```

但：

```
cash burn doubled
```

也必须进入 outcome。

---

# 41. Action Completion Rule

完成：

```
task
```

不等于：

```
decision validated
```

例如：

```
moved city successfully
```

只证明行动完成。

是否值得仍需要：

```
outcome review
```

---

# 42. Action Failure Rule

行动没有产生预期结果，也不自动意味着：

```
decision was wrong
```

可能是：

```
execution issue
wrong scale
wrong timing
incorrect assumption
structure mismatch
external change
```

必须回到 Reality。

---

# 43. No Automatic Escalation Rule

如果小 action 成功：

```
pilot success
```

不能自动：

```
full rollout
```

必须重新检查：

```
scale
capacity
reversibility
authority
minimum state
```

---

# 44. Human Confirmation Before Binding Action

以下至少应要求显式 human confirmation：

```
financial commitment
contract execution
asset movement
employment termination
relationship disclosure
private-data sharing
shared property action
formal appointment where consequential
```

具体执行能力仍取决于产品/专业边界。

---

# 45. Professional Handoff Rule

如果 Action Runtime 到达：

```
PROFESSIONAL_REQUIRED
```

则动作应变成：

```
HANDOFF
```

而不是系统自己继续执行专业步骤。

例如：

```
estate draft
→ lawyer review

regulated financial action
→ licensed professional

medical action
→ clinician
```

---

# 46. Action State Should Be Visible

客户应能看到：

```
What am I doing?
Why this scale?
For how long?
What am I watching?
What would make me stop?
What happens next?
```

而不是只有：

```
PHI OS recommendation
```

---

# 47. Customer Projection Example

内部：

```

Explore transition to independent consulting

Approved scale:
bounded pilot

Action:
8-week pilot

Scope:
max 2 clients
max 8h/week
max RM5k total spend

Observe:

hours used
family impact
recovery

Review:
week 4
week 8

Pause:
workload exceeds agreed limit

full resignation
```

客户可以看到：

> **现在已经可以开始，但开始的并不是“把整个人生一次性切换过去”。**
> 
> 目前已经达到充分程度的是一个八周、有明确边界的独立顾问试点：最多服务两个客户，每周投入不超过既定时间，也不超过已经确认的预算上限；这段时间真正需要观察的，不只是有没有收入，还包括获取客户到底有多难、实际占用多少时间，以及它怎样影响现有工作、恢复与家庭安排。
> 
> 第四周与第八周都需要重新复核。如果现实证明这个方向有效，它会获得新的证据，但不会因此自动取得“立即辞职全面投入”的资格；如果成本开始突破已经确认的边界，就应先暂停或缩小，而不是因为已经开始就继续扩大。

# 51. Canonical Runtime Rule

> **Navigation must translate a qualified decision into an action whose scope, duration, resources, authority, observation, and stopping conditions are explicit.**

中文：

> **Navigation 必须把已经取得资格的决定，转化成一个在范围、时间、资源、权威、观察与停止条件上都明确的现实行动。**

---

# 52. Canonical Smallest-Action Rule

> **When a smaller reversible action can produce material reality evidence, it may proceed before a larger commitment whose threshold has not yet been met.**

中文：

> **当一个更小、更可逆的行动已经能够产生实质现实证据时，它可以先于尚未达到门槛的重大承诺进入现实。**

---

# 53. Canonical Scope Rule

> **Action authority applies only to the scale that was actually reviewed; expansion requires renewed threshold and authority review.**

中文：

> **行动资格只适用于真正接受过审查的规模；一旦行动扩大，就必须重新检查门槛与权威。**

---

# 54. Canonical Reality Rule

> **Action is not the end of Navigation; action creates new reality that must be observed before the next decision is made.**

中文：

> **行动不是 Navigation 的终点；行动会创造新的现实，而新的现实必须再次被观察，才能形成下一轮决定。**

---

# 55. Canonical Stop Rule

> **A decision that was once qualified does not earn permanent permission to continue when reality crosses its pause, minimum-state, authority, or exit boundaries.**

中文：

> **一个曾经取得资格的决定，并不会因此永久拥有继续权；一旦现实越过暂停、最低状态、权威或退出边界，它就必须重新接受判断。**

---

# 56. Canonical Human Authority Rule

> **Navigation may prepare and structure action; binding high-impact action remains subject to explicit human confirmation and any required legitimate authority.**

中文：

> **Navigation 可以准备并组织行动，但具有现实约束力的高影响行动，仍必须经过明确的人类确认以及任何必要的合法权威。**

---

# 5. `definition`

**Outcome → Continuation** 是 Navigation 的闭环模块。它把行动以后真正发生的结果，从“这次决定的结束记录”转化成“下一轮现实读取的起始条件”。

它不只问：

> 做成了吗？

也不只问：

> 结果好不好？

它真正回答的是：

> **这个行动进入现实以后，究竟改变了什么；这些改变现在已经成为哪些新的资源、约束、责任、能力、成本、关系、选择空间与未知；下一轮 Navigation 应该从什么现实位置重新开始？**

例如：

```
Action:
进行 8 周独立顾问试点
```

八周以后，不能只得到：

```
SUCCESS
```

或：

```
FAILURE
```

因为现实可能同时是：

```
获得 2 个付费客户
收入低于原目标
实际客户获取成本高于预期
每周投入时间低于原估计
用户发现自己喜欢这类工作
家庭影响可接受
一个客户来源具有重复性
另一个客户完全偶发
```

这组结果真正做的，不是替旧决定盖章。

它们是在形成：

```
NEW REALITY
```

因此：

> **NAV-30 的核心，是让行动结果离开“评价层”，重新进入“现实层”。**

---

# 6. `navigationMeaning`

NAV-29 已经建立：

```
Decision
→ Bounded Action
→ Observation
```

NAV-30 继续完成：

```
Observation
→ Outcome
→ Reality Update
→ Continuation
→ New Navigation Cycle
```

这也正式实现 Book VIII 的核心句：

> **延续，就是结果成为条件。**

行动以前：

```
Current Reality
→ Decision
```

行动以后：

```
Decision
→ Action
→ Outcome
→ New Current Reality
```

于是新的现实又成为：

```
next Decision Object
next Current Position
next constraints
next option space
```

的来源。

因此：

> **Navigation 不是一条从问题走向答案的直线，而是一种让现实不断重新取得修正权的循环。**

# 10. Core Outcome States

建议至少区分：

```
EXPECTED_OUTCOME
BETTER_THAN_EXPECTED
WORSE_THAN_EXPECTED
MIXED_OUTCOME
NO_MATERIAL_CHANGE
UNEXPECTED_OUTCOME
OUTCOME_INCOMPLETE
OUTCOME_UNKNOWN
```

---

## A. `EXPECTED_OUTCOME`

行动产生与原预期大致一致的现实变化。

这不代表整个方向已经永久正确。

---

## B. `BETTER_THAN_EXPECTED`

现实比 baseline 更有利。

仍然需要问：

```
为什么更好？
是否可持续？
是否因为偶发条件？
```

---

## C. `WORSE_THAN_EXPECTED`

结果低于预期。

但：

```
worse than expected
≠
decision was wrong
```

---

## D. `MIXED_OUTCOME`

非常常见。

例如：

```
income improved
time autonomy worsened
```

不能压成单一 Success / Failure。

---

## E. `NO_MATERIAL_CHANGE`

行动已经执行，但没有明显改变决定相关现实。

这本身也是重要 evidence。

---

## F. `UNEXPECTED_OUTCOME`

出现行动前没有进入 scenario 的新结果。

必须允许它改变模型。

---

OPTION_SPACE_EFFECT

STRUCTURE_EFFECT
UNKNOWN_EFFECT
```

这样可以防止：

```

=

```

# 15. `decisionThresholdEffect`

Outcome 可能改变未来 threshold。

例如：

```
pilot shows stable demand
+
low actual cost
+
high reversibility
```

可能使下一阶段行动的现实基础增强。

但不能直接：

```
pilot success
→ full scale threshold automatically met
```

仍需重新跑：

```
NAV-15 Capacity
NAV-26 Sufficiency
NAV-27 Threshold
NAV-28 Authority
```

相反，如果 outcome 显示：

```
higher cost
lower recovery
more affected parties
```

则未来 threshold 可能提高。

---

# 16. `authorityBoundary`

NAV-30 可以：

- 记录结果；
- 比较预期与现实；
- 更新 Current Position；
- 修正 assumptions；
- 重新打开 Navigation；
- 更新 option space；
- 触发下一轮判断。

NAV-30 不可以：

- 因好结果永久批准方向；
- 因坏结果自动否定方向；
- 隐藏现实与模型冲突；
- 用解释系统覆盖实际结果；
- 自动扩大下一阶段行动。

---

# 17. `humanDecisionBoundary`

用户必须能够说：

```
这个结果对我来说意味着不同的事情
```

例如：

系统观察到：

```
income +20%
working time +40%
```

客户可能确认：

> 这不是我想要的改善。

因此 outcome evaluation 不只是系统测量，还必须重新读取：

```
VALUE
MINIMUM STATE
GOAL
```

但系统不能因此改变 factual outcome。

应分开：

```
FACT:
income +20%

VALUE INTERPRETATION:
not worth the added time
```

```

客户可以看到：

> **这个试点没有简单地证明“你适合”或“不适合”独立顾问工作，它真正做的是改变了你现在所知道的现实。**
> 
> 八周以后，你得到的客户数量比原先目标更高，实际现金投入也低于预算，这说明需求并不是完全不存在；但真实时间投入明显高于原估计，而且三个客户里只有一个显示出重复合作可能，因此“市场已经验证”仍然说得太早。现在新的现实不是“试点成功”，而是：需求信号变强了，时间容量判断需要修正，客户重复性仍然未知。
> 
> 这意味着下一步不应该自动扩大规模，而是重新调整服务方式与时间边界，再测试重复客户是否能够形成。行动已经完成了一件更重要的事：它让现实替原来的假设回答了一部分问题。
